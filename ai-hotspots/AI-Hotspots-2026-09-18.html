AI 热点综述 - 2026-09-18

2026-09-18 21:59 AI热点

AI 热点综述 · 2026-09-18

今天的主线只有一句话：Claude 把”会话”这件事管起来了。 Boris Cherny 宣布新的 Projects 体验开始推送并表示”我现在大量的代码就是这么写的”，Cat Wu 说 Claude 开始替你统筹所有会话，Thariq 直接点明”这是把 Claude Tag 的架构搬进了 Claude Code”。同一天的另一条线同样硬：Aaron Levie 说 agent 已经占掉推理量的多数，Guillermo Rauch 说 Vercel 的部署量在过去 10 个月里超过了之前 10 年。

一、Projects：从”管理会话”到”不再管理会话”

Boris Cherny 的两条推文（2352 赞、85 转发 与 1926 赞、50 转发）其实就是这次更新的全部卖点：

“Projects 不只改变了我与 Claude 交互的方式，也改变了我写代码的方式。我不再管理会话了。我只是把想法随手发出去，Claude 把它们拆成不同的 thread，而 project 记住了我习惯的工作方式。这就是我现在大量写代码的地方。”

Cat Wu（356 赞、10 转发）把机制讲得更清楚：

“在新的 Projects 体验里，Claude 统筹你所有的会话。我每天都在用它，因为它让我能在更高的抽象层上工作。我一次性抛出一批任务然后就走开，Claude 掌握我正在做的所有事情的上下文，我随时问它都能给出汇总的状态更新。它还有会随使用不断演进的长时记忆。”

Thariq（1041 赞、51 转发）从架构角度给了一个更锋利的定义：

“Projects 把 Claude Tag 的架构带给了 Claude Code。每个 project 有一个 agent，它管理记忆，并为具体任务孵化 subagent。 你可以要求它主动做事、按计划做事等等。它比一堆散落的 session 感觉好太多了。”

Claude 官号今天补了三条工程细节，其中两条值得单独拎出来：

  • “Thread 跑在云端，所以就算你的电脑离线它们也在继续工作；但目前还够不到你电脑上的文件或工具，也够不到你的内网。本地支持很快就来。”
  • “一个 project 是随时间长大的。每个 thread 都在向共享记忆里写入、也从里面读取——所以 Claude 能记得发布改到了周五，或者记得动 billing 服务之前该问谁。”

为什么这事比”又一个功能”重要。 过去一年，agent 产品的隐性工作量全都落在用户身上：你得知道什么时候开新会话、什么时候该重述背景、哪个窗口里还留着上次的结论。用户实际上在扮演一个手动的上下文路由器。 Projects 把这件事收回产品侧——一个 project 一个常驻 agent、一份共享记忆、一批可以并行抛出去的 thread。

而”每个 project 有 agent 管理记忆 + 孵化 subagent”这个结构，说明多 agent 编排正在从框架层（LangGraph 那类显式编排）下沉成产品默认行为：用户不需要再画图，只需要说清楚要做什么。

有一点需注意，官号明确说了云端 thread 暂时触达不到本地文件与内网。换句话说，”Projects 现在是一次上下文与记忆的整合，还不是一次执行能力的扩展”——本地支持才是真正打开使用面的那一步。

二、Agent 已经占掉推理量的多数

Aaron Levie 今天的判断（79 赞、7 转发）是这几天的延续，但这次把话说死了：

“Agent 已经构成了推理量的大多数。这会在未来一两年内迅速趋近于几乎全部推理量。世界上被消耗的 token 绝大多数将来自 agent——它们 24/7 在后台为我们执行数量难以置信的任务。

Agent 会被部署去阅读所有代码变更以保护软件安全、在企业内部工作流里处理所有数据、承担招聘与客户拓展中相当大比例的调研工作、审阅世界上每一个系统的每一条事件流与日志、在我们的个人生活里替我们执行任务——还有几百个其他用例。

新上线的 agent 消耗海量 token 的速度没有放缓。就在过去一周，我引入了好几个一个月前在技术上根本不可能实现的全新工作流。”

这条要和昨晚 Claude Projects 的公告放在一起读：一个说 agent 的用量将吞掉全部推理，另一个把 agent 的常驻形态做成了产品默认值。 供需两侧今天撞在了一起。

Guillermo Rauch 那条（508 赞、31 转发）从基建侧给出了同一个趋势的另一面：

“明年产出的软件可能比整个计算史上产出过的还要多。Vercel 花了 10 年才到 10 亿次部署，但在过去 10 个月里我们又加了 14 亿次。

这些软件里有一些会非常小、非常个人化，甚至是一次性的：一个带点 JavaScript 的 HTML 文件（’artifact’）、一份报告、一个定价计算器、一组幻灯片，一直到复杂的应用、agent 和平台。

部署速度是我们痴迷的东西之一。我们把部署、上传、分配域名、全球传播一个 artifact 的时间压到了 1 秒。”

他还补了一条很有画面感的细节：当 agent 被逼着赶紧发一个热修时，它现在可以直接 vercel --turbo --prod（79 赞）。以及那句”Vercel 就是 Java 的 Vercel”（182 赞）——硬件的规模效应和软件的产出速度，今天被两个人从两个方向确认了。Amjad Masad 的反应很短：“这就是为什么我们需要一大堆数据中心（值）。”

三、记忆的下一站：不是更多 token，而是更好的索引

Garry Tan 今天提到了一个技术方向（477 赞、20 转发）：

“Memorable 找到了一种用 embedding 而不是更多 token 来优化记忆的方法，这是一种很强的新做法。”

这条的价值在于它和 Projects 的”共享记忆”形成了对照。当前的 agent 记忆主流做法是把历史塞回上下文——本质上是”用 token 买记忆”，成本随长度线性上升。 而用 embedding 做检索式记忆，是把记忆问题从”容量问题”改写为”索引问题”。

这已经是本周第二次出现同一类论证了：昨天是”概率即输出”把生成问题改写成判定问题、成本掉一个数量级；今天是记忆问题从扩容变成检索。趋势很清楚——凡是能重新表述成检索/判定的任务，成本都会掉一个量级。

四、一个人 + 一个 agent = 一家公司

Nikunj Kothari 今天公开了他的实验（69 赞），这是”self-driving company”这个概念少见的落地样本：

“我痴迷于 self-driving company 已经一年多了……试了非常多产品，没有一个达到我的标准，于是我决定自己用 ‘claude’ in the loop 做一个。介绍我的第一个实验：nosugarforkids。

在自主这一侧，我有一个 Claude agent 每天醒来做这些事：

  • 检查目录里有没有新上架的商品
  • 剪掉可能已经下架的产品
  • 找能提升触达的新内容选题
  • 查 DataForSEO 和 Google Search Console 的表现数据
  • 写并编辑可能有用的新内容
  • 保持质量、尽量不要产出 slop
  • （新增）主动联系媒体争取外链

即使到今天零外链、完全没有社交存在感，站点已经自然增长到每天大约 6000 次曝光、60 次点击。”

（他还提了一句：这套东西同时提供了完整的 MCP 与 WebMCP，你可以直接把自己的 agent 指过去。）

值得注意的不是这个站的规模，而是agent 的任务清单本身：它现在做的事情里，只有”写内容”是生成，其余全是运营——巡检、清理、找选题、看数据、发外联。这正是 Levie 说的”后台 24/7 执行难以置信数量的任务”的家庭作坊版本。

五、其余观察

  • Google Labs 的家庭 agent（539 赞、54 转发）：新的 CC 是”为家庭而建的 AI agent”，最多可加 5 个成员，共享的 “Your Day Ahead” 晨间简报邮件、自动同步 Google Calendar 与 Tasks、在 Google Chat 里协调家务（每周餐单、学校用品清单）、按指示代为处理表单与许可单，并且区分”对所有人都成立的信息”（家庭采购清单、常去的餐厅）与”只对某个人成立的信息”（饮食禁忌、所在时区）。多用户共享一个 agent——昨天 Nikunj 提到的场景缝隙，今天由大厂给出了产品形态。
  • Thibault Sottiaux 的当天最高互动（5524 赞、88 转发）：“有人试过让 Astra 和 Fable 就完美 styleguide 达成一致，然后带 WebMCP 把它托管到某个地方吗？”——重点是 WebMCP：让网站直接暴露 MCP 接口给 agent，正在从新奇玩法变成默认期待（对照上一条 Nikunj 的”完整 MCP 与 WebMCP”）。
  • Aditya Agarwal 谈对齐：“这是解决对齐与安全的正确方式。@GoodfireAI 是领先的非前沿实验室公司，正在做这件事。这件事具有时代级的重要性。”（8 赞）——可解释性路线在今天的能力叙事之外占了一小块位置。
  • Dan Shipper 只有一句：“it’s happening!”（437 赞）——参照昨天的推文，大概是指他自己预告的那件事落地了。
  • Peter Yang 的小账本：他那只 @Muse 小熊猫”又可爱又帮我省钱——完美的组合”（17 赞）。工具类产品的留存理由，往往就是这么朴素。
  • Josh Woodward：推荐手机端的 @Gemini_Notebook（131 赞），另外一条是家庭场景的口碑（185 赞）。

小结

  1. 产品开始替用户管理上下文，而不只是替用户生成内容。 Projects 把”什么时候开新会话、背景怎么带上”这些隐性劳动收归产品侧：一个 project 一个常驻 agent、一份共享记忆、一批可并行的 thread。
  2. 多 agent 编排正在从框架下沉为产品默认。 “一个 project agent 管理记忆并孵化 subagent”——用户不再需要画图，只需要说清目标。
  3. Agent 已成为推理量的主要消费者。 Levie 的”多数→几乎全部”，加上 Vercel 10 个月产出 14 亿次部署，供给与需求两端在同一天互相印证。
  4. 量级收益仍然来自重新表述问题。 记忆从”塞更多 token”改成”用 embedding 检索”，和本周早些时候的”生成改判定”是同一个套路：换一个更窄的问题，成本掉一个数量级。
  5. “一件小事 + 一个 agent”已经能跑成一家小公司。 巡检、清理、选题、看数据、发外联——自主运营清单里，生成只占很小一部分。
  6. WebMCP 值得记一笔。 让网站直接向 agent 暴露接口，今天同时出现在一条高赞调侃和一个真实产品里。

一句话概括：今天最重要的变化是 agent 从”你调用的工具”变成”替你管理工作的角色”——它接管会话、接管记忆、接管后台运营，而人退到只负责抛出想法和判断结果的位置。
