AI 热点综述 · 2026-09-23

今天整个 AI 圈只讨论一件事：价格。

OpenAI 的 Thibault Sottiaux 宣布 GPT-6 Sol 与 Luna 上线，同时把 API 价格永久下调 50%，并给 Plus / Pro / Business 用户塞进一份”银行存好的重置额度”——这条推拿到 23309 赞、1512 转发，是今天绝对的头部。同一天，Anthropic 一侧把 Opus 5.5 设为 Claude Code 与 Claude App 的默认模型并压缩定价。

于是 Aaron Levie 写下了今天最值得抄在本子上的一段话：“每一次 AI 成本下降，你能拿去跑 agent 的场景都会戏剧性增加。这就是把杰文斯悖论用在 agent 上。”

一、50% 降价：成本下降本身就是一次能力发布

OpenAI 侧的宣告几乎没有留余地：

GPT-6 Sol 和 Luna 发布了。不只是全面显著提升，在写作和那种”你试了就知道”的综合品质上也一样。

我们同时把 API 价格永久下调 50%，让这两款模型对大量新场景可行，也让你的用量更耐用——订阅用户也一样。

还有一件事：我们正在给所有 Plus、Pro 和 Business 账号加载一份存好的重置额度。走起！（23309 赞、1512 转发）

“永久”两个字是关键。 过去两年的降价公告大多带着限时、试用、特定批次的限定词；这一次的措辞是把成本曲线往下按了一格。而额度重置这条附赠品说明了另一件事：他们很清楚真正的瓶颈不是模型能力，是用户的用量天花板。

Anthropic 一侧的应对是换默认值。Cat Wu（1308 赞、35 转发）：

Claude Opus 5.5 现在是 Claude Code 和 Claude 应用的默认模型，包括 Cowork，覆盖 Pro、Max 和 Team 套餐。我在把它当日常主力用，很欣赏它清晰的沟通能力和按我的风格写作的能力。

我们在全线产品默认使用 effort medium，智能水平与 Fable 5.1 相当但更快。相比 Opus 5，你在 Opus 5.5 上的速率限制能多用 25%。

两家的动作其实是同一个判断的两种执行：能力已经够用了，接下来竞争的是每单位成本能换回多少有效工作。 一边直接砍标价，一边用更省 token 的默认档位把同样额度拉长 25%——后者更隐蔽，但对天天写代码的人来说更实在。

Levie 把这件事的经济学讲透了（655 赞、69 转发）：

今天 AI 圈真是疯狂的一天。前沿模型大幅变便宜了——先是 Opus 5.5 的降价，现在 GPT-6 Sol 和 Luna 又把 token 价格砍掉 50%。

按可比的同任务口径，AI 的单位任务成本下降速度在技术史上是前所未有的。而每一次 AI 成本下降，你能部署 agent 的场景都会戏剧性增加。这就是把杰文斯悖论用在 agent 上。

这些改进会直接带来 AI 在经济中更广的扩散：用 agent 处理我们全部的数据、扫描代码找安全问题、读完所有日志来做决策、在工作流里跑 agent 集群……

这段话值得记住的地方在于它把”降价”重新定义成了”解锁”。 不是省了钱，而是原本不划算的任务忽然划算了：全量日志分析、全仓代码审计、把一堆非结构化数据整成结构化——这些任务过去的性价比是负的，现在刚刚翻正。判断一个降价公告是否重要，标准就是它有没有让某类任务从”不划算”变成”划算”。 今天至少有四类。

二、企业侧的账本：省 63% 的 token，任务准确率还涨了

Levie 另一条更硬，是 Box 拿 Opus 5.5 跑企业知识工作的实测（232 赞、23 转发）：

我们在 Box 用 Opus 5.5 测了一堆处理非结构化数据的复杂企业知识工作。整体上我们看到了前沿级能力，相比 Opus 5 有大幅性能提升：token 用量少 63%、啰嗦程度低 42%、快 30%。而且模型本身更便宜。

  • 金融服务 —— 尽职调查（任务准确率 +39%）：一年的交易记录，找出收购标的定价工具里每一处算错的地方。Opus 5.5 每次尝试都拿满分，用词只有 Opus 5 的一半，整体 token 少 82%。
  • 科技 —— 云成本分析（+65%）：它选对了留存计算的口径，并且全程守住了源数据的单位约定，所以最后的数字真的站得住。耗时是 Opus 5 的一半，token 少 70%。
  • 消费品 —— 客户账号分析（+17%）：合同里从没写高级/初级人员配比，Opus 5.5 从 18 人名册里把它推出来，并展示了自己用的规则；几个客户在单项问卷上打了满分 10，它选择对每个客户的回答取平均，而不是直接给那个唯一的 10 加冕。
  • 临床诊断 —— 数据分析（+15%）：它发现两组的标准差差异超过 100 倍，于是换了正确的方式重算，结果发现旱季的差异根本站不住。

这四条里最值钱的不是准确率数字，是那三次”它改掉了自己一开始的做法”。 推出口径、取平均而不是取最大值、发现方差悬殊后重算——这些动作的共同点是：模型在报告结论之前先质疑了自己的方法论。 这正是过去人类评审在 AI 输出上要花最多时间的那部分工作。当模型把这部分自己做掉，省下的就不只是 token，而是验证人力。

而”啰嗦程度低 42%”这一条，其实和准确率同样重要。在企业场景里，一个答案可信不可信，很大程度取决于它有没有把话说满、有没有把不确定的地方藏在一堆修饰里。变短通常意味着变准。

三、”用 Lean 形式化验证你的 SDK”：模型开始找人类找不到的 bug

今天最被技术圈反复转发的一条来自 Boris Cherny（3324 赞、165 转发）：

我用 Opus 5.5 把 Claude Agent SDK 用 Lean 做了形式化验证。几个短提示词 = 16 个 PR，修掉了各种 bug 和竞态条件。

TLA+ 也很好用。我有时把 Lean 和 TLA+ 结合起来，找数据流、并发和状态管理方面的问题。

这两种语言我都不熟，但 Claude 都很擅长。这个方法对形式上建模你的代码、找出人类可能根本发现不了的 bug 极其有用。

形式化验证是编程的未来吗（至少是找 bug 的未来）？

这个问题的分量在于它换了一个方向。 过去两年我们问的是”模型能不能写代码”；Cherny 问的是”模型能不能证明代码是对的”。前者是生产力，后者是可信度。而当一个人可以不懂 Lean 就让 Lean 跑起来，形式化验证从”只有博士团队负担得起的科研行为”变成了”一个下午的工程动作”。

同一件事的另一条实证来自 Peter Steinberger（850 赞、33 转发）：

升级到 macOS 27 之后 ChatGPT 有时会崩……然后 Astra 在 libuv 里找到一个大约 14 年前的 bug。

“14 年”这个数字比任何评测分数都更有说服力。 一个存活了十四年、被无数项目依赖的底层库缺陷，意味着一代又一代人类审阅者从它上面走过去而没有停下来。**这不是模型比人聪明，而是模型比人有耐心——**它不会因为”这段看起来没问题”就跳过。

Cherny 还给了另一组更工程化的对照（6778 赞、228 转发，今天转发第二高）：

Opus 5.5 是个非常好的模型，这几周一直是我的主力。

我们让 Opus 5.5 和 Fable 5.1 各自把 HAProxy 从 C 移植到 Rust。两者几乎通过了 HAProxy 的全部测试，但 Opus 5.5 用了 9.5 小时，Fable 5.1 用了 12 小时，而且成本低 51%。

“几乎通过全部测试”这句话本身就是一条关于评测的警告： 当两个模型都能跑到测试集的尽头，区分它们的不再是”能不能做对”，而是”多快、多贵、以及那些测试没覆盖到的地方谁更可能出事”。这已经是运维指标，不是能力指标了。

四、97% / 97% / 97%：能力天花板正在变成一条平线

Guillermo Rauch 今天跑了一轮新的 Next.js 评测，结果值得单独列出来（1087 赞、55 转发）：

我们重新跑了最新一轮 Next.js 评测，统计如下：
① Opus 5.5   [𝟿𝟽%]
② GPT 6 Sol   [𝟿𝟽%]
③ Fable 5.1    [𝟿𝟽%]
④ Grok 4.7     [𝟿𝟺%]

值得注意的是，Grok 便宜 2 到 7 倍。

三家并列 97%，这是今天最重要的一张表。 因为它意味着在这个特定任务上，”选哪个前沿模型”已经不再是一个能力问题。当能力曲线压平，剩下的决策变量立刻变成价格、延迟、集成成本、以及你已经在用的那套工具链。这正是今天两家同时降价的原因，也是结果：

软件再也不会死掉了。你喜欢 Google Reader？太好了，你可以生成并部署一个自己的。你的，永远是你的。（1045 赞、33 转发）

Rauch 这条讲的是另一个维度上的同一件事：当模型供给变成商品，价值就往”你能不能把它固化成自己的东西”那一侧迁移。

而 Aditya Agarwal 今天补上了这场讨论里最容易被忽略的历史脉络（41 赞、4 转发）：

今天最热的议题是”模型”的安全与对齐。但 AI / 机器学习最早的”安全”辩论其实发生在自动驾驶上。

我坐的第一趟 Waymo 真的像一次宗教体验。难以置信我们造出了在真实道路上、面对所有现实挑战仍然能工作的技术。

我觉得昨天那场对谈最有意思的部分，是 Waymo 为了有底气把两吨重的机器人以 30 英里时速放进城市环境，所建起来的那套庞大评测 / 测试基础设施。

“为了发布而建起来的评测基础设施”，这句话如果换个主语放在今天，指的是所有做大模型的公司。 Waymo 花了十年才攒够发布一辆车的信心，因为它的失败模式是物理的、不可撤销的。语言模型的失败模式目前还是可撤销的——这就是为什么它们的发布节奏可以是每几周一次。但一旦 agent 拿到真实权限（钱、生产系统、别人的收件箱），这条差异就会消失，评测基础设施的厚度会重新变成决定谁能发布的那件事。

五、一些同样值得记下的碎片

  • Thariq（4528 赞、313 转发）：正确使用模型能力的方式不是往生产环境里多发 10 倍的功能，而是花更多时间理解用户、做实验、搭原型。在能力过剩的一周里，这是最该被贴到墙上的一句话。
  • Alex Albert（890 赞、40 转发）：他用 Opus 5.5 在 Blender 里重建了 1906 年地震前旧金山 Market 街，单一提示词、不使用任何下载的网格与贴图，每个建筑都追溯到 Sanborn 火险地图、Miles Brothers 的胶片、OpenSFHistory 等来源，并标注置信度。3D 生成加上视觉理解，把”一个提示词建一个世界”从演示变成了可追溯的工程。
  • Garry Tan（111 赞）：Capy 让他的 PR 速度比单用 Codex 或 Claude Code 更快——组合工具开始比单一工具更被提及。
  • Sam Altman（3675 赞、123 转发）：创业公司天然擅长”保持小公司的锋利”，而大公司要做到这一点很难，他认为这是一个被低估的待解决问题空间。
  • Josh Woodward / Claude 官方：把”可用今天”这件事做成了一句问句——Claude Opus 5.5 今天可用。你打算探索什么？ 在降价与换默认值的一周，这种口径本身就是在争夺那部分”还没决定要用哪个模型”的注意力。

一句话总结今天： 前沿模型的智能水平已经挤到同一个区间，于是竞争从”谁更聪明”转向”谁更便宜、谁更省 token、谁更能被验证”。今天所有的降价公告、默认值切换和形式化验证实验，说的都是同一件事——当智能变成日用品，真正稀缺的是把它用对的地方，以及证明它用对了的能力。
