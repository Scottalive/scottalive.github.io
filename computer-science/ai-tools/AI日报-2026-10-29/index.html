今日热点

今天榜单的主线是「给 agent 配齐办公条件」。OpenMausBot 单日 +1,190、nightly-labs/openbot +705、CopilotKit/OpenBot +240 三条线同时在场，再加上 Claude-Code-Game-Studios 那套 49 个 agent 的职级体系，指向的是同一件事：agent 正在从「聊天框里的助手」变成「有工位、有职级、有审批流」的组织成员。另一条线是 skills 的持续分发——superpowers、impeccable、ai-design-skills 全都在做「把方法论和审美装进一个包」，而且不约而同适配了二十来个 harness。DeepTutor 以 +1,926 继续领跑，但它的更新日志透露的其实是另一件事：教育 agent 的瓶颈已经从「会不会讲」挪到了「装不装得上」。

GitHub 热门 AI 项目

1. HKUDS/DeepTutor —— 49k star，v1.7.0 把「装得上」当成头等大事

49,226 stars，今日 +1,926，Python，6,077 forks。港大数据智能实验室的作品，定位「终身个性化辅导」。

  • fork/star 比 12.3%，依然显著高于 trending 项目的平均水平（多数爆款不到 5%）。这个比例说明它是被真正部署的东西，不是被收藏的东西。教育和企业培训场景的采购逻辑就是「能不能装在自己机器上」，这一条决定了它的 star 含金量和其他项目不一样。
  • 昨天的 v1.7.0 更新日志值得逐条读：模块化安装、重构的学习工作区、Dito 的块级笔记本、带旁白的视频课程、可续传的 embedding 检查点、更可靠的辅导流程。六项里至少有四项是纯工程可靠性问题，只有「带旁白的视频课程」勉强算教学法创新。
  • 这个分布本身就是结论：一个 49k star 的教育 agent，最新版本主要在修断点续传和安装体验，说明真正的用户痛点在运维侧。embedding 跑到一半挂了要从头再来，这种问题比「模型讲得不够好」更能劝退部署者。
  • 贡献者列表里长期挂着 GitHub Actions bot，它有一条自动化的评测与数据流水线。教育产品的质量下限由题库和判分器决定，这一点没有变。

2. milind-soni/OpenMausBot —— 每个 bot 一台云电脑

7,109 stars，今日 +1,190，TypeScript，1,080 forks。自称「开源版 Grok Bot」，同时也是 Meta Muse、OpenAI dots、Cue by Manus 的开源替代，前身叫 OpenGrokBot。

  • 技术栈很直白：Electron + React 19，macOS（Apple silicon 与 Intel，签名并公证的 dmg）、Windows x64 安装器、Ubuntu 24.04 的 deb / AppImage beta。这不是一个玩具 demo，是一套按桌面软件标准发布的客户端。
  • 核心设计是「人格即实例」：侧边栏里每个 bot 都是一个真实的 agent（底层跑本地的 Claude 或 Codex），各自有人格、各自的模型、各自的一台云电脑、各自连接的应用。你像对待联系人一样跟它对话，看它干活，在关键节点上审批。
  • fork 率 15.2%，比 DeepTutor 还高。高 fork 率加上「bring-your-own-agent, local-first」的定位，说明它的用户不是来看效果的，是想改成自己的东西。
  • README 里那段免责声明很说明问题：明确声明与任何加密货币无关、没有 token、任何叫 OpenMausBot / Maus / SupaMaus 的币都与作者无关。一个 AI 客户端要在首页防币圈蹭名，这是 2026 年的现实成本。

3. CopilotKit/OpenBot —— 明确说自己是模板，不是产品

7,821 stars，今日 +240，TypeScript，1,033 forks。定位是「企业能真正拥有的 AI 助手」：形状和 ChatGPT、Claude、Grok 一样，区别在于跑在你自己的基础设施上，任何部分都能改。

  • 每个 coworker 一台自己的电脑：一个真实的浏览器（带自己的登录态）、自己的文件、只授予你批准过的工具。「Every action decided before it happens and recorded after」——动作事前决策、事后记录，这句话是整个设计的纲领。
  • 接 AG-UI 协议：任何按 AG-UI 写的 agent（用框架写的或者手写的）接进来就变成一个 coworker，有自己的频道。回答不只是散文，可以是组件。
  • README 的技术诚实度罕见：明说「A template, not a product」，没有托管版可注册，仓库里每个 workspace 都是 private，不作为依赖包发布；当前是 beta，会有粗糙边缘和 bug。还老实交代 .env.example 里 OPENBOT_SINGLE_USER=true 会把所有请求当管理员放行，只适合在本机跑，上线前必须开登录。
  • 判断：它和 OpenMausBot 解决的是同一个问题的两面。OpenMausBot 面向个人，卖的是「用起来爽」；OpenBot 面向企业，卖的是「改得动、审得了」。企业自建 agent 这条路上，缺的从来不是模型接入，是一套能过安全评审的参考实现。

4. obra/superpowers —— 方法论本身也是可分发的

描述只有一句：「An agentic skills framework & software development methodology that works」。但它的工作流设计比大多数框架都具体。

  • 流程是这样的：agent 一启动，看到你在造东西，不会直接冲去写代码，而是先退一步问你到底想做什么；从对话里逼出一份 spec，分块给你看，块小到你真的能读完；你签字后，它产出一份「给一个热情但没品位、没判断力、没有项目上下文、还讨厌测试的初级工程师」也能照着做的实施计划；强调真正的红绿 TDD、YAGNI、DRY；你一句「go」，它启动 subagent 驱动的开发流程，逐个任务推进、检查、审查，再往下走。经常能自主跑几个小时不偏离计划。
  • 那句「junior engineer with poor taste」是整份文档的技术核心。它承认 LLM 的执行力远强于判断力，所以解法不是让模型更聪明，而是把判断力提前固化到计划文档里。计划写得够死，执行者是谁就不重要了。
  • 适配面极宽：Claude Code、Antigravity、Codex App/CLI、Cursor、Devin CLI、Factory Droid、Gemini CLI、GitHub Copilot CLI、Grok Build、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse……这个清单本身就是当下的 harness 全景图。
  • 判断：它卖的不是代码，是纪律。而纪律能被 git clone 分发，这件事在三年前还不成立。

5. pbakaus/impeccable —— 62 条确定性规则，不用 LLM

装法一行：npx impeccable install，重载编辑器，再跑 /impeccable init。支持 Claude Code、Cursor、Codex CLI、Copilot、Devin、Gemini CLI、Grok Build、OpenCode、Antigravity、Kiro、Trae、Mistral Vibe、Pi、Hermes Agent、DeepSeek Harness 等近二十个工具。

  • 它解决的是「AI slop」：Inter 包打天下、紫到蓝的渐变、卡片套卡片、彩色底上放灰字、每个标题上方一个圆角方形图标块。不加额外指引让 agent 做个页面，这些东西会跨模型、跨项目稳定复现。
  • 三层设计：polish / bolder 这类动词把模糊需求变成可执行的「作业指导」——说「让它更抓眼球」，agent 只能猜；说 /impeccable bolder the pricing cards，它加载专门为这个动作写的 playbook 并只对准一个目标。critique 按可用性启发式给设计打分并排修复优先级。audit 查无障碍、性能、主题、响应式，按 P0（阻塞）到 P3（打磨）分级。
  • 最关键的一条：slop 检测是 62 条确定性规则，没有 LLM，不需要 API key。 这决定了它是可复现的、零成本的、不会今天说有明天说没有的。用 LLM 当审美判官听起来高级，但结果不稳定，做不成工程。
  • 对照案例很有说服力：同一个模型（Fable 5.1）、同一份 brief（利古里亚海岸一栋十四间房的家庭旅馆），没有它，产出是「有品位的默认值」——米色页面、细衬线、斜体点缀、胶囊按钮；有它，页面围绕一张图重建：夜里从水面看这栋房子。

6. Donchitos/Claude-Code-Game-Studios —— 49 个 agent 的职级体系

一句话：把一个 Claude Code 会话变成一整间游戏工作室。49 个 agent、74 个 skill、一套完整的协调系统，目录结构就是 .claude/agents、.claude/skills、.claude/hooks、.claude/rules。

  • 三层职级：directors 守愿景、department leads 管自己的领域、specialists 干具体的活。每个 agent 有明确职责、上报路径、质量门。你依然做所有决定，但现在有一支会问对问题的团队。
  • 作者的动机写得很坦率：一个人用 AI 做游戏很强，但单个聊天会话没有结构——没人拦着你硬编码魔法数字、跳过设计文档、写面条代码；没有 QA pass，没有 design review，没人问「这真的符合游戏的愿景吗」。
  • 判断：这是「流程即提示词」的极端形态。风险也很清楚——README 自己都得专门用一个章节回答「它产出的是游戏，还是文档？」。当质量门的产物是文档时，很容易出现文档越写越厚、可玩产物越来越远的滑坡。49 个 agent 的组织成本，最终要由「能不能跑起来一个 demo」来偿还。

顺带记一笔长尾：thedotmack/claude-mem 已经 104,287 stars（今日 +324），跨会话持久记忆支持 Claude Code、OpenClaw、Codex、Gemini、Copilot、OpenCode 等。十万 star 说明「上下文管理」已经是一个独立的基础设施层，而不再是某个客户端的附属功能。

新工具/产品速览

  • Google Connected Apps：开发者可以向 Search 和 Gemini 提交应用，用户直接在 Google 的 AI 工具里调用，形态类似已经接进去的 OpenTable 和 Instacart。美国开发者今天起可加入公测 waitlist，平台提供流量和延迟指标。皮查伊同时预告了面向消费者的新 agentic 体验，具体和现有的 Gemini Spark 差在哪还没说。
  • OpenAI dots 支持发短信：可以通过 iMessage 或 RCS 跟你的 Dot 对话，美国 Pro 用户预览开放。agent 的入口从 App 挪到了系统级消息通道。
  • GitHub Copilot app 大更新：新增 projects，可以把一个任务跨多个仓库分配；换设备能接着之前的进度；可以在 app 内创建可复用的 AI automation。
  • Maxon Cinema 4D 预告草图转 3D：上传图片生成模型，另有文本和草图作为参考的选项。社区的第一反应是版权问题：会不会允许把任何人的作品变成模型。

  • OpenAI 设选举运营中心：从现在运行到所有选票统计完毕，监控自家模型被滥用、误信息传播和异常行为。

技术洞见

一、agent 的「四件套」正在固化

把今天这几条放在一起看，会发现三家互不相干的项目在用不同话术描述同一套架构：

OpenMausBot 说的是「每个 bot 有自己的云电脑」，OpenBot 说的是「每个 coworker 一台计算机，动作事前决策事后记录」，Game-Studios 说的是「49 个 agent 有职级和上报路径」。措辞不同，四个层次完全重合。

原因不难推：agent 出错的成本已经从「答错一句话」变成「删了一个库」或「发出去一封邮件」。当失败代价跨过某个阈值，可靠性的解法就不在模型侧了，而在权限侧——隔离执行环境、限制可用工具、把高风险动作卡在人工审批上、把每一步留下痕迹。这三件事都不需要更聪明的模型，只需要更好的工程约束。

这也解释了为什么这批项目的宣传语里几乎不提模型能力。它们比的是谁的沙箱更干净、谁的审批更顺、谁的回放更完整。

二、skills 成了新的分发单位，但供应链还是空的

superpowers 是方法论包，impeccable 是审美包，ai-design-skills 是设计规范包。三者有极具一致性的特征：宿主是别人的 harness、适配二十来个客户端、安装一行命令、内容是 Markdown 和 YAML 而不是可执行代码。

这个结构和 2010 年代的 dotfiles、ESLint 共享配置生态几乎是同构的，只是宿主从编辑器换成了有 shell 权限的 agent。差别在于风险量级：一份 ESLint 配置最坏情况是把代码格式搞乱；一份 skill 是被注入到能执行命令的上下文里的作业指导，最坏情况取决于它写了什么，而没人 review 它。

现在的生态里没有任何一环做验证。没有签名，没有能力声明（这个 skill 需要读文件吗？需要联网吗？），没有版本锁定，装上去就等于信任作者。在个人项目里这是效率，在企业环境里这是审计缺口。接下来一年大概率会出现的东西：skills 的权限清单格式、签名机制、以及 CI 里那道「你的 skill 申请了哪些能力」的检查。

在那之前，唯一的防线是人的判断：装之前把那个 SKILL.md 读完。它很短，通常不到两百行——读完的成本，远低于它跑起来之后的成本。
