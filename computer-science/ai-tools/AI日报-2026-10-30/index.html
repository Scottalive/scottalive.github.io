今日热点

今天 trending 前 15 里有 11 个项目直接服务于 agent，但主线已经不是”再造一个 agent”，而是给 agent 补基础设施：impeccable 单日 +2,299，把”设计品味”做成一串可调用的命令；claude-mem 单日 +1,145，把”跨会话记忆”做成可插拔的一层；superpowers 与 mattpocock/skills 分别以 309k、307k star 占住了 skills 分发的位置。另一侧，Mistral 把 1T 参数的 Large 4 权重放了出来，而 Claude Code 官方 VS Code 扩展被投毒、Anthropic 被曝遭入侵并投递远控木马——开源权重在往前走，agent 供应链在往后漏。jailbreaks 仓库单日 +2,053 冲进榜单，正好是同一件事的另一面。

GitHub 热门 AI 项目

1. pbakaus/impeccable —— 把”品味”编译成可执行检查项（+2,299）

96,503 stars，今日 +2,299，Rust。项目自述是”给 coding agent 的设计词汇表：用 polish 和 bolder 去推进，用 critique 和 audit 去复核，在 AI slop 出厂前拦住它”。

这个仓库值得单独讲，因为它解决的是一个被普遍承认、但很少有人动手量化的痛点：AI 生成的界面不难看，难看得有规律。灰度过多的卡片、到处一样的圆角、无意义的渐变、把三个功能塞进一个按钮的文案——这些都是可以被枚举的特征。impeccable 的做法是把设计评审拆成动词：polish 是加细节，bolder 是加强对比与层级，critique 是按判据找问题，audit 是出一份可回归的清单。

三个观察：

  • 它是 Rust 而不是提示词包。语言选型说明意图：本地可执行的 CLI，能被 agent 调用，也能塞进 CI 当检查门。提示词仓库只需要 Markdown，工具仓库才需要 Rust。
  • “设计”正在被拆成可判定命题。间距是否落在 4/8 网格上、对比度是否过 WCAG AA、动效时长是否超过 300ms、标题层级是否跳级——一旦变成命题，就能写测试。设计评审从”我觉得不好看”变成”第 7 条不通过”，这是 agent 能接手的唯一形态。
  • 它同时也是”AI slop”这个概念的产品化。过去一年大家抱怨模型输出同质化，但抱怨不能进流水线。把同质化写成规则集，是同质化第一次可以被工程手段削减。

2. thedotmack/claude-mem —— 上下文从”窗口”变成”数据库”（+1,145）

105,506 stars，今日 +1,145，TypeScript。定位一句话：捕获 agent 在会话期间做的所有事，用 AI 压缩，再把相关上下文注入到未来的会话里。兼容 Claude Code、OpenClaw、Codex、Gemini、Hermes、Copilot、OpenCode。

在 2026 年下半年，”记忆”这件事的工程共识已经基本形成：不要把全部历史塞回上下文窗口，要先压缩再检索。claude-mem 的路线是标准的五段式，价值在于它把这个流程做成了跨 harness 的公共层。

值得警惕的地方也很具体：

  • 压缩即失真。把 300 轮对话压成 20 条结论，丢掉的是”当时为什么否掉方案 B”。这类信息在三个月后价值最高，也最容易被摘要器判定为噪声。
  • 记忆投毒。一旦注入链路可写，攻击者只需要让 agent 在某个网页上”记住”一条假的部署约定。跨 harness 的公共记忆层，同时也是一块跨 harness 的公共攻击面。
  • 105k star 这个量级说明它不是玩具。这个数字已经接近”基础设施”而非”项目”。

3. obra/superpowers 与 mattpocock/skills —— skills 成了新的分发层（+1,255 / +882）

309,141 stars（今日 +1,255，Shell）与 307,100 stars（今日 +882，Shell），加上 anthropics/skills 的 185,010（+287），三个仓库在做同一件事：把方法论装进 .agents 目录。

这件事的分量在于位置。一个 skill 仓库不需要模型、不需要算力、不需要 API key，它只提供”在什么情境下按什么顺序调用什么工具，以及失败时怎么退”。当三个仓库同时站在 30 万 star 量级，说明用户已经把 skills 当成安装 agent 的第一件事，而不是”进阶玩法”。

Shell 占据语言首位这一点也很说明问题：技能包的主体是可执行脚本与说明文档的组合，不是库。它更像 dotfiles 而非 npm 包——这也是为什么它们的 fork 率高、更新碎、难以统一版本。

4. HKUDS/DeepTutor —— 连续领跑的教育 agent（+2,282）

51,386 stars，今日 +2,282，Python，5,000+ forks。港大数据智能实验室的”终身个性化辅导”项目，连续两天是榜单里增速最快的正经项目。

昨天它靠 v1.7.0 的工程化改动（模块化安装、重构工作区、可续传的 embedding 检查点）吃了 +1,926，今天仍然 +2,282，说明热度不是一次性发布带起来的，而是有持续使用。教育类 agent 的 star 含金量通常高于娱乐类，因为它的用户是”要装在自己机器上给一群学生用”的机构——这直接对应 fork 率。

5. CopilotKit/OpenBot 与 macro-inc/macro —— “每个 agent 一台电脑”继续扩编（+707 / +379）

CopilotKit/OpenBot：8,507 stars，今日 +707，TypeScript。”开源的 AI 同事，每个都分到一台自己的电脑：浏览器、文件、工具，每个动作执行前先决策、执行后留记录。”
macro-inc/macro：5,721 stars，今日 +379，Rust。邮件、聊天、文档、任务、agent、通话、CRM 拼成一个工作区，共享 AI 记忆。

前天我们在日报里写过这个方向，今天它没有退潮，反而长出了第二种形态：OpenBot 走的是”审批前置”，macro 走的是”统一记忆”。两者的共同前提是agent 需要持久化的工位状态，否则每次唤醒都要重新认识环境。

6. lightpanda-io/browser —— 给自动化用的无头浏览器（+559）

37,948 stars，今日 +559，Zig。用 Zig 从零写的、面向 AI 与自动化的无头浏览器。相比把 Chromium 塞进容器，它的卖点是内存与启动开销。agent 时代的浏览器需求已经变了：不需要渲染得多好看，需要的是能开 50 个实例而不炸内存。

7. 两个非典型信号

  • togg53192-cmd/jailbreaks：10,127 stars，今日 +2,053，冲进增速前三。内容如名——一份 jailbreak 合集。它和下面行业动态里的 Claude Code 投毒事件是同一枚硬币：对 agent 的攻击面研究已经从论文走向大众化传播。
  • Renhuai123/ziwei-doushu：10,856 stars，今日 +1,146，TypeScript。紫微斗数开源排盘引擎，基于倪海厦《天纪》体系，含完整排盘算法、四化系统、格局知识库、古籍原文数据。它严格说不算 AI 项目，但它是”把领域知识做成结构化数据 + 可验证算法“的典型样本——这恰好也是知识型 agent 最缺的一层。

新工具/产品速览

Mistral Large 4（代号 Le Chonk）开放权重。1 万亿参数、原生多模态，本月早些时候以 public preview 发布，今天放出改进版权重。官方说法是：开源权重模型里编码能力第一，防御性网络安全能力也处在世界前列；提供三种推理模式以平衡成本与效果；完全开放权重、欧洲训练，支持自托管部署。

值得注意的不是参数规模，而是三点组合：1T 参数 + 开放权重 + 三档推理预算。第一点决定能力上限，第二点决定谁能用，第三点决定用得起。三者同时给，意味着”前沿能力”的稀缺性正在从”有没有”转向”跑不跑得动”。

tinyworldformer：把一个小型世界模型跑在 Raspberry Pi Pico 2 W 上。这类项目的价值不在实用，而在标定下限——世界模型到底需要多少算力才能维持一个可玩的环境，这个问题需要有人用 2MB 内存去回答。

YC Labs 的 agent swarm 实验：在 Minecraft 和 Mindustry 里跑 agent 群体。多 agent 协作的真实瓶颈一直不是通信协议，而是共享世界的状态一致性，游戏恰好提供了可观测、可回放的沙盒。

行业动态

  • Claude Code 官方 VS Code 扩展被投毒。安全研究者披露官方扩展存在供应链污染，HN 上同时出现”Backdoors in official Claude Code extensions”与 phorion.io 的详细分析。这条的分量在于”官方”两个字——当 agent 的插件市场成为默认安装路径，扩展签名与构建可复现性就是新的操作系统级问题。
  • Anthropic 被入侵并投递远控木马。与上一条同期出现在 HN 首页。攻击者选择的目标很明确：拿到 agent 的运行权限，等于拿到它连接的所有工具、仓库和凭据。
  • 美国众议院民主党人提出决议，反对为 Big Tech 的 AI 泡沫兜底。政治层面的信号：AI 资本开支开始被当作需要”风险分担”的公共议题，而不是纯粹的企业投资。
  • Azure 五处跨租户入侵（HN：”Azure’s Weakest Link”）。云厂商的多租户边界仍然是 AI 基础设施最脆弱的一段，因为 agent 工作负载天然要求跨资源的高权限。
  • “光纤能用几十年，GPU 三年一换”。一个流传的观点：AI 这轮基建和 dot-com 不同，因为底层资产折旧曲线完全不一样。反过来说，这也解释了为什么算力租赁和推理效率会成为比模型榜单更硬的生意。

技术洞见

洞见一：agent 的能力正在被拆成三层，竞争点从”模型”移到”运行环境”

看今天的榜单，15 个项目里几乎每一个都落在三层之一：

模型层在开源化，技能层在标准化，记忆层在集中化。前两层越开放，第三层就越关键——因为最终决定 agent 能干什么的，不是它读过多少方法论，而是它还记不记得自己昨天承诺过什么。这也是为什么 105k star 的记忆层和 30 万 star 的技能层会同时出现：它们互为前提。

洞见二：安全事件第一次咬在了”官方分发路径”上

今天的 Claude Code 扩展投毒和 Anthropic 入侵，值得放在一起看。过去的 agent 安全讨论集中在两处：提示词注入（模型层）和沙箱逃逸（执行层）。而这两起事件指向第三处——分发层。

一个 agent 的信任链实际是这样的：官方扩展 → 你的 IDE → 你的仓库凭据 → 你的云资源。中间任何一环被替换，后面全部失效，而且失效是静默的。当扩展安装量以百万计时，投毒的期望收益已经高到不需要定向攻击。

对应的防御手段其实老派得让人意外：扩展签名校验、构建可复现、权限最小化、把 agent 的凭据和人的凭据分开。这些都不是新东西，只是 agent 生态扩张太快，把它们跳过了。

一句总结

今天榜单给出的最有价值的信号，不是某个项目涨了多少 star，而是**”agent 的工程化”已经细化到设计品味和记忆压缩这种颗粒度**——这说明它正在从演示阶段进入运维阶段。而运维阶段的第一课，永远是安全。
