今日热点

榜单今天换了重心：前十里有一半不是在造”更强的 agent”，而是在造agent 的组织形式。Claude-Code-Game-Studios 用 49 个角色 + 72 个 skill 复刻一间游戏工作室，Orkas 用 Commander 派活给 16 个专家，OpenMAIC 把多智能体塞进课堂，清华与港大两条教育线同时冲榜。另一侧，Mistral 把 Large 4 定调为”最强开源权重编码模型”，而 Cursor 上约 5000 人装了被投毒的 Claude Code 扩展——组织能力在涨，供应链风险也在涨。

GitHub 热门 AI 项目

1. Donchitos/Claude-Code-Game-Studios —— 把”工作室”写成目录结构（+1,347）

30,758 stars，今日 +1,347，Shell 为主。一句话定位：把 Claude Code 改造成一间完整的游戏开发工作室——49 个 AI 角色、72 个 workflow skill，外加一套模仿真实工作室层级的协作系统。

这个项目值得排第一，不是因为它的点子新，而是因为它把”多 agent 协作”里最难的隐性知识，写成了文件系统。

真实的游戏工作室不是”一堆人并行干活”，而是一套交接契约：策划交出去的 GDD 必须含哪几节、美术的资产命名要满足什么规则、QA 在什么条件下可以打回、版本冻结后谁能改主线。这些东西平时藏在人脑和会议记录里，新人靠三个月的口口相传才能学会。Claude-Code-Game-Studios 的做法是给每个角色一个目录、一份职责说明、一组可调用的 skill，把”交接口”变成磁盘上的路径。agent 之间不需要互相理解，只需要读写同一个约定。

值得注意的是它的技术选型：Shell。真正的逻辑不在代码里，而在几十个 .md 和薄薄的编排脚本里。这传递了一个信号——多 agent 系统当前的瓶颈是流程设计，不是并发框架。你写多复杂的 DAG 调度器，也救不了一份含糊的交接文档。

同样要泼一盆冷水：49 个角色听起来很壮观，但角色越多，token 消耗和”互相推诿”的概率越高。真实工作室的层级能成立，是因为有人承担后果；agent 的层级如果没有强制裁决点，会退化成无限循环的”我觉得应该问一下主程”。这个仓库真正的价值，是让人第一次能以低成本看到这种退化发生在哪里。

2. Orkas-AI/Orkas —— 本地优先的”AI 团队”桌面应用（+1,004）

5,907 stars，今日 +1,004，JavaScript，MIT 协议。定位：开源的本地优先 AI 团队——一个 Commander 把你的目标拆成待办，然后协调 16 个内置专家 agent，外接 Claude Code、Codex、OpenCode、OpenClaw、Hermes，带项目、定时自动化与连接器。macOS / Windows 免费，可用内置模型或自带 key。

如果说上一个项目是”用提示词复刻组织”，Orkas 是”用应用程序复刻组织”。它做对了两件工程上的事：

  • Commander 只做拆解与派发，不做具体执行。这是控制上下文膨胀的关键——指挥官不需要读完整份代码，只需要知道”这个任务该给谁、验收标准是什么”。
  • 本地优先 + 自带 key。在云端 agent 平台开始按 seat 收费的这个季度，本地运行时是唯一能把边际成本压到电费的东西。

它的风险也很清楚：16 个专家 agent 的边界一旦重叠，Commander 的派发就会变成”两个 agent 改同一个文件”。多 agent 系统的经典故障不是能力不足，而是写冲突与重复劳动。想认真用，得先给它一套文件所有权规则——哪个目录归谁，谁改之前要先申请。

顺带说一句，它的说明里点名兼容 OpenClaw、Hermes、OpenCode 这些 harness。这类”壳”型产品的护城河，越来越不在模型接哪家，而在谁的编排协议被别人支持。

3. THU-MAIC/OpenMAIC 与 HKUDS/DeepTutor —— 教育成了多 agent 最好的落点（+115 / +1,035）

  • THU-MAIC/OpenMAIC：42,034 stars，TypeScript，清华 MAIC 实验室。开放的多智能体互动课堂，一键进入沉浸式多 agent 学习体验。今日只 +115，属于”高位盘整”，但 42k 的存量说明它已经不是实验品。
  • HKUDS/DeepTutor：52,378 stars，今日 +1,035，Python。港大数据智能实验室。定位是”终身个性化辅导”，有独立站点 deeptutor.info。

把这两个放一起看，是因为它们暴露了教育场景为什么特别适合多 agent：

  1. 角色天然存在。老师、助教、出题人、评审、同学——不需要发明人设，现实里就有，而且职责边界是社会约定好的。
  2. 反馈可以闭环。做题 → 判定 → 讲解 → 再出题，是一个能自我验证的循环，不需要外部真值。
  3. 错误代价低。答错一道题的成本远低于部署错一个服务，这让系统可以激进地试错。

OpenMAIC 走的是”课堂模拟”，用多个 agent 扮演同学来制造讨论压力——这是单模型对话给不了的东西。人对着一个 AI 讲题时不会紧张，但对着”三个会追问的同学”就会。DeepTutor 走的是”长期学习者模型”，难点在记忆：三个月前你在哪一类题型上反复出错，这件事必须留在库里，否则”个性化”就只是每轮重新猜。

这两条线的共同短板也一样：评测。多 agent 教学系统很难证明自己比单模型 + 好 prompt 更好，因为学习效果的噪声远大于系统差异。谁先把”同一批学生、同一份试卷、可复现的提升幅度”做出来，谁才算真的成立。

4. milind-soni/OpenMausBot —— agent 需要一个能弄脏手的沙箱（+1,304）

9,264 stars，今日 +1,304，TypeScript。开源版 Grok Bot 替代品，核心特征是一个给 bot 使用的虚拟机。

今日增长排第二，但它讲的是榜单里最朴素的一件事：agent 要干活，就得有台机器。

过去半年的教训很一致——只给 agent 一个 shell，它会 rm 掉不该 rm 的；只给它一个浏览器，它会被网页里的注入指令带走。可接受的做法是给一个一次性的、可回滚的、有资源上限的虚拟机：装好依赖、能跑 GUI、能截图、能被人在旁边看着。OpenMausBot 把”虚拟机”直接写进定位，说明这个方向已经从”加分项”变成”产品定义”。

这也正好接上今天的一条安全问题（见下文 Cursor 投毒事件）：执行环境就是信任边界。沙箱外的 agent 是一次授权事故，沙箱内的 agent 只是一次失败的实验。

5. thedotmack/claude-mem —— 记忆层继续吃下整个榜单（+1,723）

107,149 stars，今日 +1,723，TypeScript。捕获 agent 会话期间的全部动作，用 AI 压缩，再把相关上下文注入未来会话。兼容 Claude Code、OpenClaw、Codex、Gemini、Hermes、Copilot、OpenCode。

它昨天已经上过榜，今天反而是全榜增长第一。这说明两件事：一是”跨会话记忆”确实是当下最痛的点；二是它正在从项目变成标准——同时兼容七种 harness 的东西，实际上是在定义 agent 之间交换上下文的格式。

复用昨天的判断：压缩即失真、记忆即攻击面。今天补一条新的观察——当记忆层成为公共依赖，它的 bug 会以”所有 agent 同时开始记错事”的形式出现，这比单个模型幻觉更难定位。

技术洞见

洞见一：多 agent 的胜负手是”裁决点”，不是角色数量

今天榜单上四个项目——Claude-Code-Game-Studios（49 角色）、Orkas（16 专家）、OpenMAIC（多 agent 课堂）、OpenMausBot（VM + bot）——本质上在解同一个问题：怎么让多个执行者不互相打架。

它们的共同结构可以画成这样：

图里最关键的一个节点是 R。今天这些项目，谁把 R 写清楚了，谁就能真的跑起来；谁只堆了角色，谁就会在第三轮之后陷入”两个 agent 各自认为自己对”的僵局。

具体到工程实践，R 至少要写三件事：文件所有权（谁能写哪个路径）、冲突优先级（QA 的否定意见是否高于实现者的自检）、终止条件（几轮之后强制收敛，而不是无限循环）。这三条不写在文档里，多 agent 就只是”多开几个窗口”。

洞见二：agent 栈已经从”模型 + 提示词”变成三层基础设施

把今天的榜单按层排一遍，会看到一个相当规整的结构：

三层的关系不是并列，而是闭环：组织层决定要做什么，记忆层决定”我们上次做到哪、踩过什么坑”，执行层负责真的把事做完并把结果写回去。缺任何一层，agent 都退化成一次性对话。

这个分层也解释了今天的两条行业新闻。Mistral Large 4 解决的是模型层的能力上限；Cursor 扩展投毒发生在执行层的信任边界。有意思的是，后者的破坏力远大于前者——模型弱一点只是活干得糙，执行层被投毒是直接把你机器上的信息带走。

所以对做 agent 产品的人来说，2026 年 Q4 的优先级排序应该是：先把执行层的隔离做对，再把记忆层的检索做对，最后才去卷组织层有多少个角色。榜单上的热度恰好是反过来的顺序，这也是为什么大部分多 agent 项目活不过三个月。
