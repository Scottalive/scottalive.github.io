今日热点

今天榜单呈现出一种不太常见的整齐：前五名全是 Agent，而且全是”把 Agent 从对话框里拽出来”的项目。DeepSeek 官方放出 dsh-superagent，一个只听 GitHub 与飞书指令、自己开工作项、自己提 PR 的主动式编码 Agent，五天 2 万星；同一天排行第三的 dsh-Go 把 DeepSeek Harness 整个塞进安卓手机；Mika 干脆让 Agent 在一块隐藏的后台屏幕里替你操作微信和购物 App。

与之呼应的是一批 “Skill 化”项目：unslop 用一套设计评审流程去治 AI 生成界面的”塑料味”，floorplan 让 Agent 画代码地图，teardown 把任意机器变成可拆解的 3D 模型。能力没变，变的是分发形态——不再是库和 API，而是一份能被 Agent 直接读懂的 Markdown 技能包。

说明：今晚 github.com/trending 直连超时，榜单改由 GitHub Search API 按”近期创建 + 高星 + 持续推送”筛选得出，star 数为当前总数，不代表单日增量。新闻部分来自 TechCrunch（HN、VentureBeat 当晚不可达）。

GitHub 热门 AI 项目

1. deepseek-ai/dsh-superagent-prototype —— 会自己接活的编码 Agent

  • 语言：TypeScript（pnpm 工程）
  • 数据：20,172 Star / 2,343 Fork，创建于 2026-10-31
  • 协议：MIT
  • 定位：面向单个 GitHub 仓库的主动式编码 Agent，以插件包形式运行在 DeepSeek Harness 上

README 第一句就把免责声明摆在最前面：“Research prototype for reference only, not an official DeepSeek product”——这是研究原型，代码大量由编码 Agent 自己写出来，工程风格可能不一致。这份坦率反而值得注意：它说明 DeepSeek 内部已经在用”Agent 写 Agent 框架”的方式迭代了。

它最核心的设计不是能力，而是注意力经济。README 里有一句几乎是纲领的话：

take as little human attention as possible, and give as much value as possible.

一个能替整个团队干活的 Agent，同样也能浪费整个团队的注意力。所以它把行为边界收得很紧：只在被要求时行动，或只在团队明文写下的规则允许时行动；只在有人必须做决定、或结果真能被用上时才开口。

几个值得抄的工程细节：

  • 会话隔离：每个 work item 有自己的 agent session 和自己的工作目录，避免多个任务在同一份工作区里互相污染上下文。这是多 Agent 系统里最容易被忽略、也最容易出事的地方。
  • 回复归位：答案回到发起对话的那个线程，而不是新开一个频道。对使用者来说，Agent 的存在感被压到最低。
  • 人机边界显式化：Web Panel 不是”监控面板”，而是”待人工队列”。它承认了一件事——判断权和执行权必须分开。
  • 文档即协议：docs/000-philosophy.md 到 008-cookbook.md，按编号递进，每一篇只依赖前面几篇。用人话把设计意图写清楚，比写一堆抽象接口更有用。

2. storytold/craft-anything —— 把”逆向 + 重建”做成闭环

  • 语言：Rust（100%），跨 macOS / Windows / Linux / FreeBSD / Web
  • 数据：17,495 Star / 3,195 Fork
  • 协议：MIT OR Apache-2.0（early alpha）
  • 定位：看明白任意网站、App 或游戏怎么运作，然后让 AI 给你造一个自己的

这个项目把过去零散的三件事接成了一条自动流水线：用真实检测工具观察目标 → 编码 Agent 立项重写 → 与原目标对照、迭代修正。注意”clean-room”这个词——它在法律上很关键，意思是实现方不接触原始源码，只依据外部行为重建。Rust 写引擎则保证了跨平台分发和 Web 端的一致性。

它的价值不在于”抄”，而在于给 Agent 提供了可验证的参照系。大多数 Agent 写代码的问题是写完没人验收；craft-anything 把”原目标”变成了天然的测试用例。

3. ccch1mneyyy/dsh-Go —— 把 Agent 装进口袋

  • 语言：Dart / Flutter（安卓端）
  • 数据：12,829 Star / 585 Fork
  • 协议：AGPL-3.0
  • 定位：DeepSeek Harness 的手机外壳，本机运行，也能遥控你的电脑

它解决的是一个非常具体的痛点：Harness 类工具默认长在终端里，而终端在电脑上。dsh-Go 把它变成安卓 App，本地跑一份，远程连一份。从 topics 看（dsh-plugin、dsh-tui、coding-agent），它不只是一个 SSH 客户端，而是想把插件生态一起搬过去。

值得注意的是 AGPL-3.0 这个选择。对一个”把服务端能力下放到客户端”的项目来说，这是防止被云厂商白嫖的常规操作，但也意味着一部分企业用户会绕道走。

4. heydamir/unslop —— 治一治 AI 界面的塑料味

  • 语言：JavaScript（技能包，非运行时）
  • 数据：10,601 Star / 577 Fork
  • 协议：CC BY 4.0
  • 定位：Claude Code / Codex 技能，把”vibecoded”的界面改成有设计感的界面

这是今天最”人味”的项目。作者 Damir Sokolovsky 在 X 上连载 Unslopping 系列，把设计师做 redline review 的那套方法拆成了 Agent 可执行的步骤。它先列出所有”slop”的痕迹——紫色渐变、发光、emoji 当标签用、文案在喊叫、间距忽大忽小——再从你的产品里提炼出一个方向，最后像设计师一样一轮一轮地改。

几个设计得很聪明的地方：

  • 先给方向，再动刀：它审完屏先提方案，让人在早期就能纠偏，而不是改完一屏才发现风格不对。
  • 如果本来就好看，它会说好看：README 明确写了”如果屏幕已经不错，它只提几条小改建议，不重做”。这在 Agent 产品里罕见，因为”重做”看起来更有产出。
  • 付费动作必须确认：需要生成图片时，它会展示 prompt 并征求同意，才调用 fal / Replicate / OpenAI Images。
  • 隐藏彩蛋：Story Video 会把”界面自我净化”的过程录成一条 10 秒短视频，直接可发。这是一个把工具变成传播素材的设计。

5. wangzan101/Mika —— 后台屏幕里的手机助手

  • 语言：Kotlin（Jetpack Compose）
  • 数据：7,363 Star / 1,694 Fork
  • 协议：Apache-2.0
  • 定位：安卓端的端侧 AI Agent，替你操作 App 和网页

Mika 的技术关键点只有一句，但分量很重：它跑在一块隐藏的后台屏幕上，你可以继续用手机。 大多数手机自动化方案要么抢占前台，要么靠无障碍服务的模拟点击，要么需要 root；Mika 走的是 Android 的虚拟显示（virtual display）路线，在后台把 App 渲染出来，再读取 UI 树、执行操作。

README 里的例子都很”生活化”：一句话让它在后台打开微信找到联系人发消息；翻完一个微信群把今天的讨论总结出来；在购物 App 里按”30 美元以内、4.5 星以上”挑充电器加进购物车。这条路线的想象空间很大——端侧 Agent 的真正瓶颈从来不是模型，而是”能不能在不打扰人的前提下操作真实 App”。

6. KKKKhazix/agent-autoloop —— 让命令行 Agent 自己跟进到底

  • 语言：TypeScript
  • 数据：3,626 Star（创建于 2026-11-03，四天）
  • 定位：事件驱动的自托管 agent loop，给 Claude Code / Codex 加一层”后台值守”

它的定位很直白：让你的命令行 Agent 在后台自己接活、自己跟进到底；平时不烦你，遇到拿不准的事才发一条卡片找你拍板。技术栈是 MCP + 事件驱动 + 自托管，跟今天第 1 名的思路撞了车——大家都在把 Agent 从”你问我答”改成”事件驱动的常驻进程”。

7. haydenschmitty/floorplan —— 让 Agent 画一张代码地图

  • 语言：JavaScript
  • 数据：3,060 Star / 734 Fork
  • 定位：Claude / Codex 插件，把代码库画成一张”人话版”的交互地图

新人和 Agent 面对同一个问题：一个中型仓库有几百个文件，真正的结构藏在 import 图和调用链里，不在目录名里。floorplan 用图结构把”这个 App 到底是怎么拼起来的”画出来，比让模型读目录然后猜要可靠得多。这类工具的价值会随着仓库变大而上升。

新工具/产品速览

Underdog 放出 32MB 的语音模型 Woof。 31.7MB、3100 万参数、纯浏览器运行、完全离线，模型权重公开可下载。它甚至用这个模型做了个小游戏：房间里有一台打字机、一台 CRT 显示器、一盏台灯，你打什么字，游戏就用 Woof 念出来；转动旋钮还能生成不同风格的音乐。游戏剧情里”入侵小镇的云厂商”显然是句嘲讽。这家公司在几周前刚发布 167MB 的语音转文字模型 Bark，路线非常一致——把语音能力塞进端侧。创始人 Sigil Wen 的说法是，他不想用 Granola 那类笔记工具，想自己造一套跑在用户设备上、数据归用户所有的系统。

Claude 上线个人财务分析。 可以直接分析你的消费记录。这类”高敏感数据 + 强推理”的场景是对模型信任度的一次真刀真枪的考试。

亚马逊让用户发短信给 Alexa 帮忙购物。 值得注意的是时机——就在亚马逊屏蔽 Muse 之后。大厂对”第三方 Agent 进入自己的商业闭环”态度很明显：入口可以给，但必须是我自己的入口。

行业动态

AI 支出增速熄火，而 Anthropic 正走向 IPO。 Ramp 的数据显示，8 月和 9 月企业 AI token 支出只涨了 1.5%，而 7 月的环比增速是 42%。10 月略有回暖（9/23 到 10/23 涨 8.9%），但趋势线已经变了。Ramp 首席经济学家 Ara Kharazian 的判断很尖锐：

几乎所有 AI 支出都来自风投支持的高增长科技公司。只要支出继续涨，这没问题；可一旦因为市场或其他因素开始放缓，它们会同时放缓，然后引发连锁反应。

分层数据更能说明问题：中位数企业每人每月只花 12~15 美元，前 10% 花 600~1000 美元，而最”AI 上头”的前 1% 曾达到每人每月近 1 万美元——8、9 月已经跌破了这条线。而前 1% 的轻微回落，”足以让整体收入增速熄火，哪怕用量还在涨”。

换句话说：用量在涨，收入不涨。 这是价格战和客户成熟共同作用的结果，也是所有按 token 计费的商业模式迟早要面对的剪刀差。

其他动作：

  • Palo Alto Networks 正洽谈以 5 亿美元 收购 AI Agent 安全公司 Clutch——Agent 安全开始被当成正经的安全品类来买了。
  • OpenAI 总裁 Greg Brockman 称公司可能在 2027 年具备 IPO 条件。
  • OpenAI 发布了一款面向网络安全的专用模型（业内对其效果仍有争议）。
  • Meta 收购 AI 编码公司 Conductor；Dropbox 以 3.5 亿美元 收购 Tigris Data 补 AI 基础设施。
  • Agility 成为第一家纯人形机器人上市公司。
  • 苹果据报正在削减内部 AI 使用的预算。

技术洞见

一、Agent 的分发单位，正在从”库”变成”技能”

把今天前七名排在一起看，会发现一个共同的形状：

unslop、floorplan、teardown、skills 四个项目没有一个是运行时，全部是 Markdown + 少量脚本 + 参考资料。它们不需要你 npm install，只需要被 Agent 读到。这意味着：

  1. 分发成本接近零，一个仓库就是一次安装；
  2. 质量取决于流程设计，不取决于代码量，所以设计师、咨询顾问也能做”开发工具”；
  3. 护城河变浅，但组合价值变高——真正的差异在于”这套流程有没有被验证过”。

而 dsh-superagent 与 agent-autoloop 代表另一半：Harness 本身在平台化。Agent 不再是终端里的一个会话，而是一个监听事件、持有工作目录、能自己开 PR 的常驻进程。dsh-Go 则把同一个 Harness 搬到手机上。框架、技能、外壳三层已经分层了，这是生态成熟的信号。

二、两条曲线正在交叉：端侧小模型 vs. 云端大账单

今天的两条新闻放在一起非常有意思。一边是 Underdog 把语音模型压到 31.7MB，浏览器里离线跑；另一边是 Ramp 的数据显示企业 AI 支出增速从 42% 掉到 1.5%。

这条链的结论并不悲观，但很明确：当”够用的智能”变得极其便宜，卖 token 的生意就会先撞墙，卖结果的生意才有定价权。 Mika 那种”后台屏幕替我操作 App”的产品，卖的是”这件事被办成了”，不是”我调用了多少次模型”——定价模型天生更抗跌。

对个人开发者来说，可操作的判断有两条：

  • 别在通用能力上做产品，去做”端侧 + 特定 App/流程”的组合，那里云端厂商下不来；
  • 把交付物从”接口”改成”结果”，技能包这种分发形态恰好最适合这种转型。
