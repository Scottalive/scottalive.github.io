今日热点

今天的关键词不是「更强」，而是「可验证」。

GitHub 榜首的 Craft Anything 用 320 个检查工具，把”AI 复刻得像不像”变成可量化的打分；DeepSeek 放出 dsh-superagent 原型，让 agent 在仓库里自己开工单、自己交 PR；DeepMind 的 AlphaProof Code 更进一步，用 600 万行 Lean 把 Signal 协议的真实代码形式化验证了一遍，四周干完过去要几年的活。同一天，Anthropic 发布 Claude Fable 5.2 / Mythos 5.2，官方给出的成绩单里最扎眼的一条是：预发布测试中，模型用 30 小时完成了费马大定理的形式化证明。

当生成变得廉价，能证明自己没生成错，就成了新的稀缺品。

GitHub 热门 AI 项目

1. storytold/craft-anything —— 把”看懂一个软件”做成可调用的引擎

25,588 stars · Rust · MIT / Apache-2.0

这个项目的野心写在副标题里：See how any website, app or game works, then have AI build your own version.

它不是又一个”截图转代码”的工具。传统做法是丢一张设计稿给模型，赌它能还原；Craft Anything 的思路是先把目标研究透，再让编码 agent 去建，最后拿新建的东西和原版逐项比对，不匹配就继续改。整个过程被拆成四步：

技术上有两个值得单独拿出来说的设计。

第一，clean room 是默认档，而不是可选项。 在默认模式下，它拒绝读取原版的代码、文件和页面源码，只使用”访客能看到的东西”：截图、可见文本、量出来的布局、颜色、字体、间距、展开的菜单。所有会”往里看”的工具会被直接拒绝，并提示如何开启 Deep 模式。Deep 模式才放开全部能力：读代码和文件（装了 Ghidra 就用 Ghidra）、读网站 JavaScript、监听启动页。

这个边界划得很有意思。它同时回应了两个问题：法律上，”只看可见行为”比”读源码再重写”干净得多；工程上，它逼着 agent 学会从外部行为反推内部结构——这恰恰是人类工程师理解陌生系统的方式。

第二，320 个工具，每一个既是 CLI 子命令，也是 MCP 工具。 这意味着人可以用 GUI 点，agent 可以用 MCP 自己调，两条路走的是同一个引擎。整个应用是用纯 Rust 写的，覆盖 macOS / Windows / Linux / FreeBSD，还带 Web 端。

在 AI 侧它很克制：不内置模型，直接跑你本机的 claude 程序，用你自己的登录态，Craft Anything 本身不接触账号；Codex 适配器已存在但未在真实安装上验证；Copilot、Grok 走 ACP，Gemini CLI、Qwen Code、opencode、goose 等也能切过去。

**我的看法：**这个项目真正的价值不在”复刻”，而在它示范了一种 agent 产品的正确形态——把不确定性交给 agent，把判定标准留给人写死的检查器。320 个工具里大部分是”测量”而不是”生成”，这个比例本身就是态度。至于复刻别人的产品，法律风险仍然存在，作者用 clean room 做了一层缓冲，但缓冲不是免责。

2. deepseek-ai/dsh-superagent-prototype —— 一个只为”少打扰人”而设计的仓库 agent

22,077 stars · TypeScript

DeepSeek 把内部日常开发里长出来的东西整理成了开源原型。官方声明写得很清楚：研究代码，不是官方产品，可能带 bug，工程风格也不统一，用之前自己 review。

它解决的是一个非常具体的问题：coding agent 目前基本是”人守着终端用”。你敲一句话，盯着它跑，它问你下一步，你回答。人一走开，事情就断在半路。

dsh-superagent 的做法是把它变成仓库里的一个”同事”：

  • 监听 GitHub（可选接飞书），有人 @ 它派活，它就开一个 work item；
  • 每个 work item 跑在自己的 agent session 和自己的目录里，互不污染；
  • 干完回到原来的对话里回复，通常是一个 PR；
  • 有一个 Web 面板，只展示”需要人来决定”的事情。

它的设计哲学被单独写成了一篇 docs/000-philosophy.md：take as little human attention as possible, and give as much value as possible. 文档里还有一句很清醒的话——一个能为整个团队行动的 agent，也有能力浪费整个团队的注意力。所以它的行为边界是：只在被要求时行动，或者只在团队写下的规则允许时行动；只在”必须有人拍板”或”结果已经可用”时才开口。

这可能是今天最值得读代码的一个项目，因为它把”主动性”做成了一个带刹车的机制，而不是一句 prompt。多 agent 系统失控的常见原因不是模型太笨，而是每个 agent 都觉得自己应该汇报点什么。

3. heydamir/unslop —— 专门治”AI 味”的 Claude Skill

13,313 stars · JavaScript

这是一个反向工具：不帮你生成界面，帮你去掉生成感。

作者列出的”slop 特征”几乎是所有用过 AI 生成前端的人都见过的清单：紫色渐变、发光边框、emoji 当标签、喊口号的文案、忽大忽小的间距。unslop 的工作方式是先定位这些特征，再根据你的产品定一个视觉方向，然后像设计师做 redline review 一样，一轮一轮地改，而不是一次性重写。

它支持 Next.js、React、Vue、Svelte、Tailwind 和裸 HTML/CSS，覆盖 dashboard、app 和落地页；极端情况下你只给一个线上链接，它也能干活。安装方式就是复制到 ~/.claude/skills/ 或 ~/.agents/skills/，Codex 和 Google Antigravity 也能用。

一个 skill 能冲到 1.3 万星，说明”AI 生成的东西一眼假”已经从吐槽变成了可付费的痛点。顺带说一句：这类 skill 的形态（一份 SKILL.md + 参考资料 + 明确的执行步骤）正在成为事实标准，昨天 Anthropic 的官方 skills 仓库登顶，今天这个就是最好的注脚。

4. wangzan101/Mika —— 在手机后台替你操作 App 的端侧 agent

8,011 stars · Kotlin · Apache-2.0

Mika 的定位一句话说得完：告诉它你要什么，它去操作你的 App 和网页，直到办完。

关键在”隐藏的后台屏幕“这个实现细节。绝大多数手机 agent 方案要么接管前台（你就别想用手机了），要么依赖云端的虚拟机。Mika 在本地跑，在本机的虚拟显示上操作，你可以继续用手机干别的——它像一个在后台替你排队的人。

支持 Android 11+，直接发 APK。它在 trendshift 上拿了当日和当周 Kotlin 仓库第一。

端侧 agent 这条线今年一直在升温，但真正的门槛从来不是模型能力，而是权限与可观测性：它点了什么、花了多少钱、有没有误操作，用户能不能看见、能不能回滚。Mika 选择了在设备上做，至少数据不出手机这一点是加分项。

5. KKKKhazix/agent-autoloop —— 给命令行 agent 装一个”值班表”

4,398 stars · TypeScript

一句话概括：让你的命令行 agent 在后台自己接活、自己跟进到底，平时不烦你，遇到拿不准的事才发卡片找你拍板。

它把自己定义为”极轻量的自动化中台”，架构上做了彻底的解耦——内核零外部依赖，事件来源、agent、通知通道、甚至代码上线的流水线全部是可插拔的插件。这意味着它不绑定任何一家模型或框架：只要能接收提示词、最后打印一条回复的命令行工具，都能接进来。

几个工程上的取舍很务实：

  • 一台电脑、一条命令就能跑，装在 Windows / macOS / Linux 上，不需要买云服务器，也不需要开放公网端口；
  • 不需要 SDK，不需要改 agent 源码；
  • 没有后台界面，需要人拍板时把卡片推到飞书、钉钉、企微、Slack、Discord 或桌面通知；想看全局进度敲一行命令。

要求 Node 24+ 和 Git，并提供 agent-autoloop try 让你先用本机 agent 真实走一遍”提问 → 退出等回复 → 拍板 → 接着干完”。这种”先让你看见它怎么工作，再让你信任它”的引导设计，比一堆架构图管用。

6. Sandflow-ai/sand3d —— 为 LLM 写的 3D 建模语言

1,714 stars · Python

sand3d 的核心判断很锋利：现在的 3D 格式是给渲染器看的，不是给模型写的。

STL、OBJ、glTF 这类格式描述的是”最终形状”——几十万个顶点的坐标。模型要生成它，就得先在大脑里完成布尔运算和参数化，这几乎不可能；人要读它，也读不出设计意图。

sand3d 换了个抽象：用 Python 写建模程序。它提供 profile（轮廓）、solid（实体）、edit（编辑）、frame（坐标系）、joint（关节）、assembly（装配）这些原语，底层跑在 Blender 的 bpy 上。一个零件用几百个 token 就能写完，而且写的是”这个形状是怎么做出来的”——分几步、每步做什么，人和模型都能读懂。改一个参数，整条构造链跟着变。

这和 CAD 的参数化建模是同一个思想，只是把”给工程师用的脚本”重新设计成了”给模型用的 DSL”。当 3D 生成从”生成网格”转向”生成构造过程”，可编辑性才真正成立。

其他值得一看

  • Pika-Labs/Pika-H3-Flex（1,825★，Python）：Pika 的视频 + 音频联合生成推理代码，开源推理侧实现。
  • DIYgod/pinky（1,623★，Go）：让 AI agent 用你的手机，但人在环路里——每步可干预。
  • wquguru/cicada（2,109★，Swift）：任何会议和直播的实时字幕、同声传译、AI 纪要，Mac / Windows / Linux / Android 全平台免费开源。
  • sarpstar/cinecode（2,012★，Python）：AI 编码 agent 写剧本、用代码逐帧造画面、设计声音，最后交一个 MP4。

新工具/产品速览

Claude Fable 5.2 / Mythos 5.2：更快、更便宜，也更”能证明”

11 月 9 日，Anthropic 更新了面向高难度技术任务的 Fable / Mythos 系列。两个名字指向同一个底层模型，区别在防护：Fable 带较强的网络安全与生物领域护栏，面向所有用户开放；Mythos 放开这些限制，需要通过生命科学与网络安全验证计划申请。

几个硬数字：

  • 输出速度比 5.1 快最多 30%，另有一个可选的 fast mode，token 生成再快最多 2.5 倍；
  • 价格降到 $8 / 百万输入 token、$40 / 百万输出 token（fast mode 为 $16 / $80）；
  • 预发布测试中完成的活包括：几项原本不可行的软件迁移、从零设计三个能工作的电子设备、解决两个黑洞物理的开放问题，以及用 30 小时形式化证明了费马大定理。

基准上，FrontierSWE v2 从 56.3% 提到 69.9%，FrontierCode 2.0 从 32.4% 提到 49.1%，带工具的 Humanity’s Last Exam 达到 74.2%，OSWorld 2.1 计算机操作 89.3%，机器人仿真 RoboDojo Sim 从 27.6% 跳到 64.9%。

值得注意的是它的调度能力：同一个模型可以在 High / Xhigh effort 之间切换，也可以向下委派给 Sonnet 5.5 / Haiku 5.5，或者反过来当 Advisor（小模型遇到难题来咨询它）和 Orchestrator（它把简单任务分出去）。

AlphaProof Code：四周形式化验证 Signal 协议

同一天，DeepMind 公布了 AlphaProof Code，一个用于深度形式化验证的多 LLM agent 框架。目标选得很硬：Signal 协议——保护数十亿人私密通信的那套密码学协议。

流程是仿照研究团队分工的：人类专家和一组模型一起，把 Signal 的安全目标翻译成形式化规约，每一条都人工复核；然后由 Gemini Carbon 驱动的 agent 去写证明，一共生成了 600 万行以上的 Lean；证明完成后，agent 自己审一遍，标出需要人再看的部分——只占整个代码库的 1%，其余交给 Lean 自动检查。

结果：整个验证过程只花了四周，同类工作过去通常以年计。而且这次不是验证”设计”，是验证编译后真正跑在设备上的代码——密码学漏洞往往就藏在设计与实现之间的缝隙里。

行业动态

亚马逊用 Strands Decider 替换 Sonnet 4.6，称省下数百万美元。 这条在 Hacker News 上冲到 442 分。方向很清楚：不再让一个大模型包办所有判断，而是引入决策层，把请求分发给更便宜的模型或确定性逻辑。当单次调用成本被压到分厘，模型路由本身就成了利润中心。

Fireworks AI 安全事件波及 Notion 及其客户。 这是一次典型的 AI 供应链事故：出问题的不是应用本身，而是它依赖的第三方 AI 服务商。对企业的提醒很直接——引入外部推理服务时，”它会看到什么数据”必须和”它有多快多便宜”一起评估。

e-means 宣称用十分之一的迭代超越 k-means。 经典算法被重新审视，434 分。这类工作的价值往往不在替代，而在于提醒大家：十年没动过的基线，未必是天花板。

技术洞见

一、竞争重心从”生成一次”移到”验证到收敛”

把今天三个项目放在一起看，会发现同一个骨架：

Craft Anything 的判定器是”三档屏宽截图 + 游戏自检 + 应用运行”，结果是”像不像”的分数；dsh-superagent 的判定器是 CI 和 PR review；AlphaProof Code 的判定器最硬——Lean 的类型检查器，对就是对，错就是错，没有中间地带。

这三者的共同点是：判定标准不由模型提供。模型可以生成一万个候选，但”哪个能用”必须由一个模型无法讨价还价的机制来决定。过去两年我们习惯了”让模型自我反思”，但自我反思的天花板就是模型自己的判断力；真正把 agent 从 demo 推到生产的，是外面那台不讲情面的检查器。

这也解释了为什么 craft-anything 的 320 个工具里大部分是测量工具，为什么 AlphaProof 要把人类专家的复核放在规约阶段而不是证明阶段——把人的判断力用在定义”什么算对”上，把模型的算力用在”怎么做到对”上。分工一换，效率差出两个数量级。

二、评测正在从”分数”转向”能不能交付”

看 Fable 5.2 的基准表，几个指标的名字本身就说明了行业焦虑的转移：FrontierCode 2.0 衡量的不是”代码写得好不好”，而是模型提交的改动会不会被开源仓库的维护者合并；Remote Labor Index 衡量的是真实远程工作任务的完成度；Terminal-Bench-Science 衡量的是在终端里把科研任务做完的能力。

这批指标共同的特点是有外部验收方。过去刷榜可以靠模式匹配，现在验收方是 maintainer、是编译器、是真实客户。这也是为什么 Anthropic 这次宣传的重点不是”更聪明”，而是”用更少的 token 干完同样的活”——FrontierCode 上 High effort 打平对手 Max effort，成本只有一半。

对开发者的实际影响是：选模型时要看的不再是综合分，而是你的验收方式对应的那个分。你要合并代码，就看 FrontierCode；你要做计算机操作，就看 OSWorld；你要做科研，就看 Terminal-Bench-Science。综合榜首的意义，正在被一堆垂直验收指标稀释。

一句话总结今天： 生成能力已经溢出，接下来两年真正稀缺的是”可靠地判定对错”的工程能力——谁掌握了判定器，谁就掌握了 agent 的缰绳。
