今日热点

今天 GitHub 榜单上最集中的信号是：agent 的”标准库”正在成型。

Meta 把内部用了八年的设计系统 Astryx 开源，README 第一句话就是”为人与身边的 agent 而建”；shadcn 的 improve 与 Addy Osmani 的 agent-skills，把”怎么审代码、怎么写规格、怎么交付”写成 agent 能直接执行的技能包；Vercel 补上”手”——一个常驻的浏览器；OpenAI 补上”体检”——一套能自动扫描并验证漏洞的安全工具链。同一天 Hacker News 上还有一篇：48 个 agent 指向 NASA 的 LiDAR 数据，72 小时找出一座未被测绘的玛雅金字塔。

生成能力早就不稀缺了。把工程规范装进 agent 的脑袋，才是今天真正在发生的事。

GitHub 热门 AI 项目

1. meta/astryx —— 为”人和 agent 一起写界面”准备的设计系统

24,307 stars · +2,842 today · TypeScript · MIT

Astryx 不是新项目，它是 Meta 内部长了八年的东西：公司里最大、用得最多的设计系统，支撑 13,000+ 个应用。今天它被完整开源，定位写得很直白——fully customizable and built for how we build now: by people and the agents working alongside them.

技术栈是 React 19 + StyleX（Meta 自家的编译期 CSS-in-JS），开箱提供 150+ 个无障碍组件、品牌级主题与设计 token，还带一个在线 Storybook 和沙盒。目前是 Beta。

值得单独说的是它为什么在这个时间点开源。设计系统过去服务两类人：设计师和前端工程师。现在多了第三类消费者——agent。agent 不会”看”设计稿，它需要的是结构化的组件清单、明确的 props 约束、可机器校验的用法示例。一个设计系统如果只有视觉规范，agent 用起来就会随机发挥；只有当组件 API、禁用组合、无障碍要求都被写成可检索的文本，agent 生成出来的界面才可能和团队既有风格对上。

**对前端团队的实际意义：**如果你的组件库还没有把”什么场景该用哪个组件、什么写法是错的”写成文档，那么它就只是给人看的库，agent 用不上。Astryx 真正开源的不是 150 个组件，而是一套”agent 可读”的设计系统组织方式。

2. shadcn/improve —— 把”最贵的模型”用在写计划上

10,488 stars · +333 today

这个项目的判断非常锋利：计划才是产品，代码不是。

它的分工是这样的：

用起来是一组斜杠命令：/improve 做全量审计并排优先级，/improve quick 只扫热点，/improve deep 逐包逐类过一遍，/improve security 专注安全，/improve branch 只看当前分支的改动，/improve next 反过来给功能建议。装法是 npx skills add shadcn/improve，写出来的计划是纯 markdown，任何支持 Agent Skills 格式的 agent 都能接手，加 --issues 还能把计划直接发成 GitHub issue。

它的设计里有一条很克制的原则：这个 skill 自己从不改代码。因为一旦”判断”和”执行”混在同一个上下文里，模型就会倾向于证明自己刚才的判断是对的。拆开之后，昂贵的判断只做一次，剩下的是可重复、可并行、可回滚的体力活。

3. addyosmani/agent-skills —— 把资深工程师的肌肉记忆写成 9 条命令

115,614 stars · +788 today · JavaScript

Addy Osmani 这套东西的野心比名字大得多：它试图定义软件开发生命周期的 agent 版本。

9 条命令对应六个阶段，每条命令会自动激活相关技能。/spec 强调”先写规格再写代码”，/plan 要求拆成原子的、可验证的小任务，/build 一次只推进一片，/test 的口号是”测试就是证据”，/constraints 把质量门槛一次性定死，/review 关注代码健康度而不是风格挑刺，/webperf 强调”先测量再优化”，/code-simplify 负责收尾。

它跟 shadcn/improve 是同一枚硬币的两面：一个管”这个仓库哪里值得改”，一个管”一个功能从想法到上线该经过哪些关口”。两者共同说明了一件事——技能包（skills）正在成为新的分发单位。以前我们分发 npm 包，现在我们分发”让 agent 表现得像个靠谱工程师”的行为规范。

5. openai/codex-security —— 把安全审计做成可编排的流水线

11,444 stars · +20 today · TypeScript

OpenAI 放出的是一整套东西：Codex 里的安全工作流、@openai/codex-security CLI、TypeScript SDK，以及一个 GitHub Action。

能力覆盖得相当完整：扫描整个仓库、指定路径或仅 Git 改动；深度扫描会重复标准扫描并做去重；验证候选发现、生成补丁、验证已有修复；草拟 SECURITY.md、保存威胁模型；按你自己的评分标准判严重程度，并从源码和 Git 历史里推荐负责人；支持导入第三方扫描器结果，导出 SARIF / JSON / CSV；还能把发现同步到 Linear、Jira、GitHub。

这里最值得注意的不是功能清单，而是”验证“被放在了和”发现”同等的位置。绝大多数扫描器只负责报告问题，而误报率高的直接后果是团队逐渐无视告警。让 agent 先把候选漏洞跑一遍、能复现的才留下，再自动生成补丁并回归验证——这条链路一旦跑通，安全扫描才可能从”季度体检”变成 CI 里的常驻环节。

6. homeassistant-ai/ha-mcp —— 87 个工具，把智能家居交给对话模型

7,015 stars · +640 today · Python

基于 FastMCP 写的 Home Assistant MCP 服务器，暴露 87 个工具，覆盖设备控制、自动化编辑、配置查询等。装好之后，Claude、ChatGPT 或其他支持 MCP 的助手可以直接”看懂”你家里的实体和自动化规则，并按自然语言改动。

一个细节很能说明这类项目的成熟度：v7.3.0 把 ha_config_set_yaml 挪进了 beta 通道。也就是说，直接改写 YAML 配置被认定为高风险操作，需要显式开启。这种分级比”全部开放”要负责任得多——智能家居是少数几个 agent 出错会直接影响物理世界的场景。

其他值得一看

  • GoogleChrome/modern-web-guidance-src（1,475★，+133，TypeScript）：Modern Web Guidance 的源仓库。Chrome、Edge、Firefox 与 MDN 团队共同维护的一套技能包，把现代 Web 平台能力和兼容性数据直接塞进编码 agent，专门治”模型偏爱 2019 年的写法”。提供 npx modern-web-guidance install、search、retrieve，还有一个 legacy-scan 可以扫出代码库里的过时模式。
  • ZhuLinsen/daily_stock_analysis（69,853★，+960，Python）：LLM 驱动的多市场股票分析系统，多源行情 + 实时新闻 + 决策看板 + 自动推送，强调零成本定时运行。这类”个人投研助手”是今年增长最快的一类应用形态。
  • we-promise/sure（12,575★，+1,079，Ruby）：今日增量冠军，但不是 AI 项目，而是一个开源个人理财应用。它出现在榜单上本身就是个提醒：AI 热潮之外，扎实的产品依然能靠口碑冲榜。

新工具/产品速览

Claude 补齐办公三件套。 Anthropic 上线 Claude Whiteboards、Claude Sheets 与 Claude Data 三项能力，把协作画布、表格与数据处理并进对话式工作流。方向很清楚：模型不再只是”回答问题”，而是要在同一个界面里承接”讨论—整理—计算”的连续动作。HN 上 255 分。

Apple 要给 Mac 做一个跑本地模型的应用。 据 9to5Mac 报道，Apple 正在准备一款让普通用户也能在本机运行 AI 模型的 Mac 应用（HN 363 分）。如果落地，本地推理会从”极客的 Terminal”变成”双击就能用”，这对隐私敏感场景和离线场景意义不小。目前仍是报道阶段，具体能力与时间表未定。

行业动态

48 个 agent、72 小时、一座金字塔。 一位 Google 工程师在博客里记录了这件事：把 48 个 AI agent 指向 NASA 公开的 LiDAR 地形数据，让它们并行做异常检测与交叉验证，72 小时后定位到一处此前未被测绘的玛雅建筑结构（HN 244 分）。方法本身不神秘——大规模并行 + 互相验证——但它示范了 agent 的正确用法：不是让一个模型更聪明，而是让一群普通模型互相纠错。

AI 挖漏洞开始形成”窗口期”问题。 VulnCheck 发文通报 Anthropic 相关漏洞发现的跟踪情况（HN 429 分）。当模型能系统性地发现真实漏洞，从”被发现”到”被修复”之间的时间差就成了攻击面。这与今天开源的 codex-security 指向同一个结论：AI 安全工具的竞赛，重点不在谁先发现问题，而在谁能让修复跑得比利用快。

Val Town 宣布关停。 这个把函数即服务做成”社交化脚本”的平台在 HN 上拿到 404 分。它不算 AI 项目，但对做 agent 工具的人有直接参考价值：依赖第三方托管执行环境的自动化，会随平台生命周期一起消失。 把关键流程留在自己能控制的地方，是对冲这类风险最朴素的办法。

技术洞见

一、skills 正在成为新的分发单位

今天榜单上有四个项目在做同一件事：把某种”专家行为”打包成 agent 可加载的规范。

Meta 打包的是设计系统用法，shadcn 打包的是审计与写计划的流程，Addy Osmani 打包的是整个开发生命周期，Chrome 团队打包的是 Web 平台知识。它们的共同点是：内容比代码重要，格式比实现重要。

这解释了一个看起来矛盾的现象——模型越来越强，技能包却越来越火。原因在于模型强的是”通用推理”，弱的是”你们团队的具体约定”。你没法在 prompt 里每次都交代”我们的组件库禁用哪个组合””这个仓库的测试怎么写””哪些 API 在 Safari 上有坑”，但你可以把它写成一份 skill，一次写好，所有 agent 长期复用。

于是分工变了：模型负责推理，skills 负责品味。前者靠厂商军备竞赛，后者只能靠团队自己积累——这也是为什么这一层不会被某一家模型厂商吞掉。

二、能力分层，正在替代”一个模型包打天下”

把 shadcn/improve 和 codex-security 放在一起看，会看到同一套编排逻辑：

三个层次的关键差异在于成本结构。规划层只跑一次，可以贵；执行层要跑几十上百次，必须便宜；判定层根本不消耗模型，是确定性的程序。把这三种东西混在一个上下文里，结果一定是”用最贵的价格做最便宜的判断”。

这条路的尽头，是 agent 系统不再以”用了哪个模型”来评价，而以”编排得好不好”来评价。同样是 GPT 级别的底座，有人做出来的东西一天烧掉几百美元还经常跑偏，有人用十分之一的成本稳定交付——差距不在模型，在分层、在缓存、在什么时候该把决定权交还给一段 if 语句。

写日报这些天，我越来越确信一件事：未来两年 AI 工程的护城河，既不在模型里，也不在 prompt 里，而在那些”模型碰不到”的地方——你写死的检查器、你积累的 skills、你设计的分层边界。这些东西没有一个能靠 API 调用买到。

一句话总结今天： 当所有人都在等下一个更强的模型时，真正拉开差距的是把工程规范、成本结构和验收标准一层层焊进 agent 的工作流里。
