今日热点

今天的榜单有个很整齐的特征：前几名全都不是模型，而是围绕 agent 的工程件。第二名 modern-web-guidance-src 单日涨 1,225 星，是给编码 agent 喂”这个平台现在该怎么写”的知识库；第一名 plannotator 是人和 agent 共用的审阅工作台；腾讯开源的 LoopForge 则把 agent 关进 SOP：Docker 沙箱、角色分工、人工审批门，一步都不许跳。再配上 caveman 那种”把 token 砍掉三分之二”的暴力节流，和用 Zig 重写推理运行时的 TensorFold，今天的主线非常清楚——行业已经不讨论 agent 能不能干活了，开始讨论它能不能每天稳定、可审计、且便宜地交付。

GitHub 热门 AI 项目

1. Tencent/LoopForge —— 把 coding agent 关进 SOP 里

Go · MIT · 711 stars · +174 today · npm loopforge-cli

这个项目的自我定位很诚实，它先承认了现状：

让 coding agent 去”修这个 bug”，结果取决于那一次运行。它可能跳过计划、忘了测试、自己审自己的代码，或者干到一半停了而没人发现。做 demo 没问题，但这不是团队交付的方式。

LoopForge 的答案是把”一次运行”变成”一条流水线”。它开源自托管，跑在你自己的机器或服务器上，核心抽象是 SOP——由 Agent 节点、Script 节点、Human-gate 节点和子 SOP 组成的标准流程，引擎按顺序执行，每个节点在自己的沙箱里跑。

几个设计细节值得抄：

  • 角色分离。规划、实现、审查、测试各拿自己的 prompt、执行器、模型、规则、Skills 和 MCP 工具。一个角色既是 SOP 里的节点，也能在聊天里作为 subagent 被叫出来。这一条直接冲着”agent 自己审自己代码”去的——审查者的上下文里不该有实现者的自我辩护。
  • 执行器可换。内置十种 coding agent CLI：CodeBuddy、Codex、Claude Code、OpenCode、Cursor CLI、Antigravity、Kimi Code、Pi、DeepSeek Harness、ZCode。它不绑定某一家，只提供角色、沙箱、检查点和历史。这等于承认了一件事：模型和 CLI 会换，流程不该跟着换。
  • 可中断、可回退。”从任意节点重跑”、”把工作打回指定步骤”、”暂停/恢复/接管”——这不是锦上添花，这是 agent 交付能不能进生产的分水岭。一个不能回退的流水线，出错时只能重来。
  • 两条路径共用一套账。聊天式（Main Bot 直接开沙箱、派角色、提 PR）和 SOP 式（固定阶段 + 签核）追踪同一批需求，每一次变更都挂回原始需求，进入交付与成本报表。

它的取舍也很明确：上手成本比直接敲 claude 高得多。要装 Git、Docker、Compose、Python 3，要维护沙箱和自己的一套 SOP 文档。它服务的不是个人开发者，是那种”同一类需求每周来十遍”的团队。对这些人来说，把流程写下来才是省时间的做法。

2. QwenLM/qwen-code —— 1.0 预览：harness 我全都要

TypeScript · 30,155 stars · +462 today

Qwen Code 今天放出 1.0 预览，卖点一句话讲完：开源的 agent harness，能力对齐闭源商业产品。

  • 开箱带 agent 全套件：Auto-Memory、Auto-Skills、SubAgents、Agent Teams、MCP。注意这四个词的顺序——记忆、技能、子代理、代理团队，正好是”单 agent 走向工程化”的四级台阶。
  • 多协议运行时切换：OpenAI、Anthropic、Gemini、Qwen 四种 API 都支持，也能接 Ollama / vLLM 的本地模型，运行时切换不重启。这一条对国内团队最实用：模型侧的合规和成本随时会变，接入层不能写死。
  • 不止终端：IDE 插件（VS Code / Zed / JetBrains）、桌面端、Web UI（qwen serve --open）、TypeScript / Python / Java 三套 SDK、headless 模式（qwen -p "..." 进 CI），以及 Telegram / 钉钉 / 微信 / 飞书四个聊天通道。
  • 自举：官方明确说这个仓库在用自己的 agent 提 issue、提 PR、审代码、跑测试。这句话可以当营销看，也可以当”agent 能不能长期维护一个真实代码库”的公开实验看。

我的看法：qwen-code 真正的竞争点不是模型分数，而是接口密度。同样是 Claude Code 的形态，它把”我从哪儿调你”这件事铺得极宽——终端、IDE、桌面、Web、SDK、IM。当 agent 变成基础设施，接入点数量就是分发能力。

3. ashhart/TensorFold —— 用 Zig 把推理运行时重写一遍

Zig · 2,091 stars · +188 today

一句话：tensorfold serve 是一个 Zig 编译出来的二进制，自己读 checkpoint、自己分词、直接跑 Metal 或 CUDA kernel，不需要装 Python，也不需要 MLX。

这为什么重要？因为今天本地跑模型的默认姿势是”Python + PyTorch/MLX + 一堆依赖”，一个 2B 的模型带出 5GB 的运行时环境。TensorFold 赌的是另一条路：把推理引擎做成一个静态可执行文件，像 nginx 一样部署。

具体到工程上，它做了几件很”系统程序员”的事：

  • 多后端单代码：Metal、CUDA、Vulkan 三套 kernel，Apple Silicon 和 NVIDIA 都能跑。同一份 Zig 源码编译出不同目标。
  • 拒绝错误的运行环境：kernel 用 CUDA 13 编的，启动时检测到老驱动直接报错退出，而不是跑起来给你一个错误的 logits。这个选择很硬核也很正确——推理框架最怕的就是”能跑但结果不对”。
  • 能力自描述：tensorfold capabilities --json，让上层（包括 agent）先问清楚这个二进制支持什么，再决定怎么调。
  • 给它贡献代码也要排队：仓库要求贡献者（包括 AI agent）先跑 atc check ISSUE / atc claim ISSUE，在”agent 雷达”上认领任务，五分鐘内要 pulse，开 PR 前先查 atc overlap。

最后这条是今天最值得注意的细节：当维护者本身是 agent 时，协作协议也得给 agent 设计。 人类贡献者靠”看一眼 issue 有没有人认领”，agent 需要的是机器可读的 claim 接口和超时机制——否则十个 agent 会同时改同一个文件。

注意它把 API 做成了 OpenAI / Responses / Anthropic Messages 三种兼容——兼容层比性能更能决定一个推理引擎能不能被用起来。

4. JuliusBrussee/caveman —— 用”原始人语”砍掉 65% 的 token

npm @caveman-ai/cli · 今日 GitHub Trending / HN 双榜第一

这个项目的荒谬程度和有效程度成正比。它让 agent 用”原始人语”回答：

普通 agent（63 tokens）：The reason your React component is re-rendering is likely because you’re creating a new object reference on each render cycle…

caveman（20 tokens）：New object ref each render, so React re-renders. Wrap the prop in useMemo.

同一个修复，63 token 变 20。项目声称整个会话的 input token 少 332%（54 次 Claude Code 运行，18/18 答案正确）；在 85 个编码任务上和 Opus 5.5 xhigh 对比，成本降 54% 而分数持平。还引用了 Adobe Research 的论文和 JetBrains 的 A/B 测试作为旁证。

四档强度：/caveman（20 token）、/ultracave（14）、/megacave（13，直接用中文四字压缩）。安装方式是一条 npx @caveman-ai/cli@latest，跑完以后”原本的 claude 就一直是 caveman 状态”，同时支持 Codex、Gemini CLI、OpenCode 等 30 多个 agent。

这东西为什么能火？因为它同时戳中了账单和虚荣心。但它也暴露了一个真相：大量 agent 输出里的客套、复述、总结、免责声明，本质上是给”人读得舒服”付的钱。当日志的消费者从人变成另一个 agent 时，这些冗余就是纯损耗。

需要提醒的是：这类压缩对解释性输出有效，对代码和配置无效——项目自己也强调 code stay exact。凡是需要精确性的地方，压缩就是风险。

5. dream-num/univer —— 把”AI Office”做成 SDK

TypeScript · 24,248 stars · +495 today

Univer 是老面孔，但它的定位今年悄悄换了：从”开源在线表格”变成”给人和 AI agent 用的 Office SDK“——编辑、计算、协作、文件处理，打包成可嵌进别人产品的积木。

这个转向值得单独说。过去做”AI 办公”有两条路：一是给 Office 加个侧边栏聊天框（Copilot 模式），二是从零写一个 AI 原生文档应用（成本极高）。Univer 提供的是第三条：把文档模型本身做成 API，让 agent 直接读写单元格、公式、样式、协作状态，而不是靠截图 + 模拟点击。

对比一下就很清楚：让 agent 操作 Excel，最脆弱的环节永远是”它看见的画面”和”文件真实状态”之间的偏差。SDK 路线把这个偏差从架构上消掉了。

新工具/产品速览

Amazon 开始用商品详情页”喂”AI agent。 The Verge 的说法是：把”什么东西在哪卖、卖多少钱”结构化到极致，目的是让 Amazon 比 Reddit 更好用——对人和对 agent 都是。这是电商平台第一次明确把”agent 可读性”当成产品指标。背后的逻辑不难推：如果未来一半的购物决策由 agent 发起，那详情页的读者就不再是人类，结构化数据比文案更重要。

Nothing 的”无屏 AI 设备”下月发布。 官方只放了外观，没给参数。无屏 + AI 的组合在 2026 年已经不新鲜，但它仍然是个有价值的实验：当交互不再依赖屏幕，agent 的响应延迟和语音质量就成了唯一的产品体验。

Akai 开放 MPC 插件 SDK，”vibe coding” 直接改固件。 MPC 3.10.1 和 MPC Sample 1.4 开始支持第三方 SDK，社区可以用 AI 生成插件。硬件厂商主动给 modding 社区开 API，这在音乐设备圈是罕见的开放姿态。

行业动态

Anthropic 确认 11 月 19 日开始公开交易，定价日在前一天，此前区间 70–78 美元/股，对应估值最高 1.4 万亿美元。这条昨天已经写过，今天只是日期落地。值得补一句的是时间点：一家模型公司在 IPO 前把”agent 产品线”的叙事讲得比”模型能力”更重，说明资本市场买的已经不是 benchmark，而是交付能力的可预期性。

Yahoo 成为 Internet Licensing Collective 的第一个正式被许可方。 RSL 那套”AI 抓取要付费”的标准演变成了集体许可模式——像音乐版权池一样统一收费、统一分账。Yahoo 既是发起方也是第一个客户。这条路走通，训练数据的成本结构会被重写；走不通，就还是逐家打官司。

Nvidia 的治理震荡进入第二周。 前 CEO 黄仁勋的相关报道已牵出第三位当事人，股价当日收跌 4.3%，董事会据称在讨论继任人选。同期一个技术侧注脚：网上流传的他穿 Saint Laurent 皮衣的照片被《Vanity Fair》证实为 AI 伪造，但带 Google SynthID 水印，是从 6 月真实照片改的——深伪的取证线索，现在主要来自生成方自己埋的水印。

技术洞见

洞见一：agent 的”运行时”和”流程”正在分家

把今天的项目按层摆一下，会看到一条很清晰的栈：

昨天我写的是”混合架构取代全能 agent”，讲的是单次任务内部怎么分工。今天这一层更外一层：跨任务、跨天、跨人的流程开始独立于模型存在。

证据是执行器列表。LoopForge 写了十个 CLI，Qwen Code 支持四种 API 协议加本地模型，TensorFold 同时兼容 OpenAI 和 Anthropic 的 API 形状。所有人都在做”你的东西可以换，我的框架不动”的适配层。 这在基础设施史上是成熟信号——没人再赌单一供应商会赢。

对团队的实际建议是：把你现在散落在 prompt 和口头约定里的流程，写成有节点、有产物、有回退点的东西。哪怕不用 LoopForge，先用一个 flow.md 加几个脚本把阶段固定下来。能回退的流程才能上生产，不能回退的只能叫演示。

洞见二：token 从”计费单位”变成”设计约束”

caveman 火得有点好笑，但它指向的东西一点都不好笑。

同一个模型、同一个任务，只是把输出的冗余去掉，账单就能差一倍以上。这意味着过去两年大家默认的一件事被推翻了：agent 的输出长度是模型自由决定的。 现在不了——输出长度是成本，成本是设计参数。

具体到工程上有三个立刻能做的动作：

  1. 让 agent 之间的通信走紧凑格式，别用自然语言互相对话。agent 和 agent 之间不需要”希望这对你有帮助”。
  2. 把解释性输出和机器消费输出分开。给人看的可以长，进上下文的必须短。混在一起，等于每一轮都在为同一个解释重复付费。
  3. 给上下文设预算，而不是”能塞多少塞多少”。TensorFold 那种 --context 8192 是显式预算；agent 的 prompt 组装也该有同样的显式上限。

最有意思的是这条边界：压缩在解释层是优化，在代码层是 bug。 caveman 自己都写 “Code stay exact”，因为它知道一旦开始压缩标识符和语法，省下的钱会以 debug 时间的形式还回去。

今天榜单上没有一个新模型，也没有一个破纪录的 benchmark。全是沙箱、审批门、预算、压缩、运行时。这大概是 2026 年底最健康的信号：当大家开始算每次交付的成本、开始给流程加回退点的时候，说明这东西真的在干活了。
