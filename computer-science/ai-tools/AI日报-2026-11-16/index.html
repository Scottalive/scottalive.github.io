今日热点

今天的榜单有个很值得注意的信号：昨天上榜的项目，今天几乎原样又在——ag-ui、plannotator、univer、stitch-skills、SkillEvaluator、chrome-devtools-mcp、claude-trading-skills 一个没掉，而且大多还在加速。这说明 Agent 基础设施这一层开始固化，先发者靠协议和生态位吃复利，而不是靠功能迭代。

但榜单里真正的新变化在另一条线：Agent 的能力边界正从”文本”推到”二进制资产”。kajisho5/ffmpeg-skill 把 FFmpeg 的 42 个能力封成机器可读契约，让 coding agent 能剪视频、上字幕、调响度；univer 单日 +1,878 星，把电子表格和文档引擎重构成”给人和 agent 共用”的办公 SDK。加上 SkillEvaluator 涨幅从昨天的 +133 跳到今天的 +953——当 agent 开始动媒体文件和企业数据，质检就从”锦上添花”变成了”上线前提”。

GitHub 热门 AI 项目

1. dream-num/univer —— 把办公套件拆成 Agent 可用的 SDK

TypeScript · 27,516 stars · +1,878 today · 2,508 forks

今天涨幅第一，也是连续第二天大涨（昨天 +1,041）。它的定位这句话写得很准：“Build your own AI office with Univer Office SDK”——把编辑、计算、协作、文件处理带进你的产品，给人用，也给 AI agent 用。

为什么这件事比”给表格加个聊天框”难得多？因为传统 office 套件的接口是为人的手设计的：菜单、快捷键、选区、拖拽。而 agent 需要的是另一套坐标系：

  • 可寻址：模型得能说”把 B2:F40 里大于 100 的单元格标红”，而不是”用鼠标拖选那一块”。范围要能被程序精确表达。
  • 可幂等：同一个操作跑两次结果要一样。人类操作靠撤销栈兜底，agent 批量操作必须靠语义幂等 + 事务回滚。
  • 可解释：如果 agent 改错了公式，用户要能看到”它改了哪几个单元格、为什么”。这就需要有 diff 的能力，而不仅是”最终状态”。

Univer 的做法是四层拆开：表格引擎（公式计算）、文档引擎（富文本）、协同层（OT/CRDT）、文件处理（xlsx/docx 导入导出），全部通过 SDK 暴露。

我的判断：公式引擎和协同 OT/CRDT 这两块，是那种”看起来简单、做起来两年”的东西。对想做垂直行业 AI 办公（财务、供应链、教育、医疗表单）的团队来说，自己从零写引擎基本是自杀，而 Univer 这类 SDK 是唯一现实的起点。星数的爆发说明市场已经把这条路认了下来。

2. NVIDIA/SkillEvaluator —— 质检层突然被”发现”了

Python · 2,303 stars · +953 today（昨天 +133）

昨天我把它排在技能生态的”治理环节”，今天的涨幅给了个漂亮的验证：+133 → +953，一天之内涨了七倍。 这类基础设施项目的曲线通常就是这样——平时没人关心，一旦有人踩了坑（装了 60 个技能、行为开始不可复现），就会集体涌进来。

它的四个能力点，放在”agent 开始操作真实资产”的背景下看更有意义：

  • Quality Gates：技能能不能被正确路由到、参数是否自洽、依赖是否可满足——这是准入。
  • 语义重叠检测：装多了之后最大的问题不是坏技能，是两个技能都能接同一个请求，模型随机选，行为不可复现。
  • 合成评测集生成：没有测试集就没有评估，但没人愿意手写用例。合成是唯一现实路径，代价是评估本身的可靠性也要打折。
  • Live agent evaluation：最终看”装了它之后 agent 的行为变了多少”。这要求可重复的任务环境和行为度量，是目前最难的一环。

值得记的是这条因果链：当 agent 的能力从”说几句话”扩展到”剪视频、改表格、发代码”，一次坏技能的成本就从”答得不好”变成”素材被删、数据被改”。 治理需求从来不是被”最佳实践”推动的，是被事故推动的。

3. kajisho5/ffmpeg-skill —— 给 Agent 装一双手去动视频

Python · 6,249 stars · +331 today · 547 forks

今天最有意思的新面孔。一句话：面向 coding agent 的本地视频编辑器——42 个 FFmpeg 工具，配机器可读契约和 MCP server，支持 Claude Code、Cursor、Codex。剪辑、字幕、改画幅、响度、平台导出。无云端，无 API key。

FFmpeg 是那种”能力极强、接口反人类”的典型：-vf 滤镜链、-filter_complex 多路复用、-map 流选择、时间基与色彩空间……人类靠抄 Stack Overflow 活着。而 agent 面对它时的问题不是”不会用”，是每个参数都可能有十种看起来合理但语义不同的写法，且错了不会报错，只会输出一个能播但有问题的文件。

ffmpeg-skill 的价值在于把”能力”翻译成”契约”：每个工具声明输入形状、参数约束、预期输出和失败模式。agent 不再需要发明命令行，而是在有限的、可校验的工具集里选择。

那条回环是重点：它把”执行完还要验证一遍”写进了流程。 视频处理最阴的坑是”命令成功、结果不对”——码率崩了、音画错位 200ms、字幕字体回退成方框。一个带结构化回执的技能，比一个”看起来很懂 FFmpeg”的 prompt 靠谱一个量级。

顺带说：这个项目证明了一类正在成型的市场——“给 agent 封装的本地重工具”。Blender、ImageMagick、pandoc、LibreOffice、7z、sqlite 都符合这个画像：能力稀缺、CLI 复杂、无云依赖、输出可校验。谁先把这些封成可靠契约，谁就吃下 Agent 落地里最脏也最刚需的一段。

4. ag-ui-protocol/ag-ui —— 连续第二天，协议开始收网

TypeScript · 18,484 stars · +790 today

昨天 +393，今天 +790，速度在加快。AG-UI 解决的是”agent 在后台跑，前端怎么把过程演出来”：把 agent 生命周期定义为一组标准事件流（run 开始/结束、文本增量、工具调用、状态快照与增量），前端按事件渲染，后端按事件发。

和 MCP（向下接工具）、A2A（横向接 agent）放一起，这张拼图就完整了：MCP 管”能做什么”，A2A 管”找谁做”，AG-UI 管”人怎么看见”。 三个方向各一个协议，缺一个系统就不闭环。

这类协议项目的星数曲线有个规律：它不是被”喜欢”推上去的，是被”接入”推上去的。 每一个新接入的宿主（框架、SDK、低代码平台）都会带来一批必须用它的人——这就是所谓的网络效应，也是为什么先发优势在这一层特别硬。

5. backnotprop/plannotator —— 人机共审的”旁路”

TypeScript · 12,285 stars · +689 today

连续第二天上榜。它承认了一个很少被正面讨论的事实：agent 不需要”更多自主”，它需要”更好的中断点”。

一个能跑 40 分钟的 agent，如果最后只给你一个 diff，中间 39 分钟就是黑箱；但如果它每 5 分钟停下来问”我理解得对吗”，体验就退化成电话会议。真正好用的是异步、结构化、不打断执行的旁路：agent 继续跑，你在旁边把意见攒着，在关键节点一次性回灌。shaping → decide → plan → annotate → review → share，一条链下来，本质是把”人的判断”变成 agent 可消费的输入格式。

6. google-labs-code/stitch-skills —— 开放标准是最大的卖点

TypeScript · 9,615 stars · +540 today（昨天 +248）

Google Labs 的技能库，配套 Stitch MCP server。真正的卖点在那句”每个 skill 都遵循 Agent Skills 开放标准，兼容 Antigravity、Gemini CLI、Claude Code、Cursor”。

翻译一下：Google 在自己最不占优势的那一层选择了不竞争。 它没搞私有技能格式绑定自家 CLI，而是对齐跨厂商标准。它赌的是”技能可移植性”比”格式所有权”更值钱。工程上最值得抄的是技能与 MCP 的解耦方式：技能只声明”我需要哪个工具、什么参数形状”，由宿主注入实现——同一份技能在不同宿主里跑，只是接线不同。

7. ChromeDevTools/chrome-devtools-mcp —— 57K 星的老面孔

TypeScript · 57,478 stars · +837 today

榜单星数最高。一句话：把 Chrome DevTools 暴露成 MCP 工具，让 coding agent 真正”看”得见浏览器——控制台错误、网络瀑布、DOM、Performance trace、内存快照。

它连续多天稳定在 +700~+800，说明这不是一波热度，而是大量团队在把它接进日常流程。对比一下：很多”更聪明的 agent 框架”只有几千星，而它 57K。原因很简单——能被程序调用的调试器，比聪明的模型更稀缺。

8. tradermonty/claude-trading-skills —— 垂类技能包的需求验证

Python · 6,042 stars · +841 today

给股票投资者和交易员的 Claude Code 技能集：市场分析、技术图表、经济日历、筛选器、策略开发。昨天 +707，今天 +841，持续走高。

它说明垂类技能包是个真需求：通用 agent 不知道你的行业怎么干活，而行业里那些”隐性流程”恰恰是最值钱的部分。 但必须提醒一句——这类技能的产出是分析而非投资建议，回测过拟合和幸存者偏差在 LLM 手里只会更隐蔽，真金白银的决策别外包。

技术洞见

洞见一：Agent 的能力边界，正从 token 推向文件系统

把今天的新面孔排一下，会看到一条清晰的扩张路径：

ffmpeg-skill 站在第三层的门口，univer 站在”结构化数据 + 二进制文件”的交界，chrome-devtools-mcp 是第二层到第三层的桥。而每一层的失败代价是指数级的：说错一句话，用户重问；改错一个表格公式，财务重算；删错一段素材，素材没了；发错一条公告，收不回来。

这解释了为什么 SkillEvaluator 今天涨了七倍——能力越往物理世界走，治理就越不能靠”相信模型”。 一个具体的工程建议：给 agent 的每个”写”能力配一个”读回验证”的工具。写完文件读一遍哈希，改完表格重算一遍总额，导出视频 probe 一遍时长和响度。回执比自信可靠。

洞见二：Agent 技术栈开始分层，每一层都长出了自己的”标准件”

连续两天的榜单重合度，让这张图已经可以画得比较实了：

四层里，接入层和治理层是最”没有想象空间”但最卡脖子的两段。能力层最热闹（每天都有一堆新技能包），编排层次之，但一个 agent 系统真正能不能上生产，取决于最上面那层人看不看得见、最下面那层坏东西拦不拦得住。

对个人开发者，方向选择上还是那句话：“给 agent 做接口”的确定性高于”给 agent 做大脑”。 大脑那一层全球只有几家能玩；接口那一层，FFmpeg、PDF、Excel、日志、时序数据库，每一个都还缺一个靠谱的契约封装，而且每一行代码都在产生复利。
