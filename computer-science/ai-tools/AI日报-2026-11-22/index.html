今日热点

今天榜单有一条暗线：安全的 Agent 化在攻防两侧同时发生。Claude-BugHunter 以 +1,721 继续霸榜，同一周微软把 Perception 推到正式可用、EY 上线 Agentic Cyber Defence Centre；而 Railway 被偷走的 AI Key 烧掉约 74 万美元，账单归属成了新问题。另一条线是技能被平台收编——Google 的 stitch-skills、Cursor 的 plugins 都在把「个人技能文件」变成有规范的分发单元。

GitHub 热门 AI 项目

1. Claude-BugHunter —— 第四天榜首，判例库比模型更值钱（+1,721 Star）

elementalsouls/Claude-BugHunter 今天 1.69 万 Star、单日 +1,721，连续第四天站在增长榜首。当前版本是 82 个技能、15 个斜杠命令、681 份已披露漏洞报告的模式库，覆盖 24 个核心漏洞类别，外加企业身份与基础设施的攻击矩阵。

一个值得注意的细节：技能数从昨天的 83 变成 82。多数项目在霸榜期只会做加法，它做了减法。考虑到它的技能全部从真实披露报告中提炼，删掉一个技能通常意味着某条攻击路径已经在目标环境里失效，或者被平台判定为「不构成有效发现」。技能的半衰期，就是漏洞生态的半衰期。

这也是这类项目最容易被误读的地方。它的价值不在「教模型怎么打」，而在把隐性的判据写成显性的检查项：什么算重复、什么算信息不足、什么复现步骤会被 triage 拒掉。681 份报告的模式库本质是一部判例法，而不是一本工具手册。模型会换代，判例的折旧慢得多。

边界同样要说清楚：技能包只回答「怎么想」，不回答「能不能做」。授权范围、披露时机、法律责任，一个字都不在 SKILL.md 里。

2. firecrawl —— 单日 +910，Agent 的瓶颈换位置了

firecrawl/firecrawl 今天 20.66 万 Star、+910，是全场绝对增量第一。它的自我定位已经从「爬虫」改成了「Knowledge infrastructure to make your agents smarter」——搜索、抓取、解析，550+ 数据源统一成一个 API。

这个转型说明了一件很实在的事：当模型能力足够时，Agent 失败的第一原因不再是「不会推理」，而是拿到的上下文是脏的。网页里的导航栏、广告、cookie 弹窗、动态渲染的空壳，全都会被当成事实喂给模型。抓取层的真正工作量在清洗与结构化，而不在 HTTP 请求。

但「550+ 数据源」也意味着它正在从工具变成中间商：谁被聚合、谁被优先返回、内容方拿不到分成——这些问题在搜索时代已经演过一遍。Agent 的输入层正在长出它自己的分发权力。

3. superpowers —— 32 万 Star 的方法论，说明流程可以规模化

obra/superpowers 今天 32.39 万 Star、+785，Shell 实现。它把「头脑风暴 → 写计划 → 执行 → 测试先行 → 系统性调试 → 代码审查 → 完工验证」做成一套可加载的技能文件。

32 万 Star 这个量级值得停下来想一想：它不是框架、不是 SDK，只是一组 Markdown 加脚本。这说明开发者真正缺的不是能力，而是顺序。模型最稳定的失败模式是跳过理解直接写代码、跳过失败用例直接写实现、在勉强跑通时宣布完成——这些全是流程问题，不是智力问题。

它的内在张力昨天已经说过，今天补一条：流程越严格，越需要路由。改一个 typo 走完整 TDD 是纯损耗。所以这套东西的成熟形态不是「全量加载」，而是「按任务类型选路径」——而这恰好是接下来要讲的平台化问题。

4. CLI-Anything —— 给每个软件现造一个 CLI（+687 Star）

HKUDS/CLI-Anything 今天 6.25 万 Star、+687，口号是「Making ALL Software Agent-Native」，配套还有一个 CLI-Hub。

它选的技术路线很反潮流：不搞视觉点击，不搞屏幕理解，而是给每个软件补一层命令行。理由其实很硬——CLI 是唯一同时满足「可无头运行、输出可结构化、中间态可观测、操作可复现」的接口形态。相比之下，让 Agent 看截图点按钮，是最后手段，不是方案。

代价也很明显：每个软件都要有人写一次 harness，还要跟着上游版本维护。这是一门不性感但极其扎实的手艺，而且每完成一个，就永久解锁一类工作流。

5. last30days-skill —— 研究型技能的样板（+673 Star）

mvanhorn/last30days-skill 今天 7.24 万 Star、+673，Python 实现。它做一件事：给定任意话题，并行检索 Reddit、X、YouTube、Hacker News、Polymarket 和开放网络，然后合成一份有依据的摘要。

把 Polymarket 列为信源是个很聪明的设计——赔率是用真金白银表达过的判断，它比评论区情绪稳定得多，也比新闻标题更早反映预期变化。

这条流水线的关键不在「能搜」，而在最后两步：来源打分与交叉验证。多源检索最容易产生的错觉是「信息很多所以可信」，实际上三个来源互相抄袭同一个错误博客的情况非常常见。研究型技能真正的护城河，是它知道哪些来源在什么议题上不可信。

6. stitch-skills 与 cursor/plugins —— 平台开始收编技能

google-labs-code/stitch-skills（1.17 万 Star、+516）是 Google Labs 为 Stitch MCP server 提供的技能库，遵循 Agent Skills 开放标准，兼容 Antigravity、Gemini CLI、Claude Code、Cursor。同一天，cursor/plugins（1.83 万 Star、+301）发布了插件规范与官方插件。

两个大厂在同一天做同一件事，信号很清楚：技能正在从「个人 dotfiles」变成「有规范、有版本、有分发渠道的软件包」。一旦有了插件市场，随之而来的必然是权限声明、依赖管理、签名与审计——也就是 npm 生态花十年才学会的那套东西。

7. minimind —— 两小时训一个 64M 模型（+473 Star）

jingyaogong/minimind 今天 6.84 万 Star、+473：从零训练一个 64M 参数的语言模型，两小时跑完。

64M 不是产品，是教具。在所有人都通过 API 调模型的年代，亲手跑一遍 tokenizer、注意力、反向传播、学习率调度，是校准直觉的唯一方式。很多关于「模型为什么这样回答」的争论，本质上是因为争论者从没见过 loss 曲线长什么样。

8. 其他值得一提

  • cathrynlavery/diagram-design（7.0 万 Star、+513）：45 种编辑级图表模板，自包含 HTML + SVG，README 里那句「No shadows. No Mermaid slop.」骂得直白。有意思的是本文还在用 Mermaid——静态博客管线里零依赖、可版本化，这个理由依然成立。分工是清楚的：Mermaid 负责「随手画清楚」，它负责「拿出去给人看」。
  • mjmirza/app-store-compliance（3,729 Star、+617）：上架拒稿判例库，已扩到 124 种拒稿模式、112 个跟踪中的合规截止日期。内容还在长，说明这类「把行业潜规则编译成检查表」的需求是持续性的。
  • openvinotoolkit/openvino（1.2 万 Star、+155）：Intel 的推理优化与部署工具箱重新上榜，端侧推理的热度在回流。
  • toeverything/AFFiNE（7.66 万 Star、+537）：Notion + Miro 的开源替代，文档、白板、数据库同一数据模型——这是 Agent 能有效读写知识的前提。
  • zhouxiaoka/autoclip（1.32 万 Star、+640）与 XiaoYouChR/Ghost-Downloader-3（1.48 万 Star、+690）：一键出片与下载器。内容生产与内容搬运的自动化，仍是最大的民间需求。
  • Tracer-Cloud/opensre（1.42 万 Star、+395）：CI/CD 可靠性 Agent，SRE 排查流程的技能化落地。

新工具/产品速览

微软在 Ignite 2026 发布 Perception，并宣布正式可用。 它把安全信号、环境信息和调查/响应 Agent 串成一条链路：可以隔离设备、吊销身份访问、在授权层封禁 Agent。微软声称自有与合作伙伴数据源每天提供 165 万亿条信号、500+ 连接器，中间加一层为 Agent 优化的「上下文层」——官方强调精度、召回与 token 效率，但这属于厂商自述。

更值得看的是权限设计：高影响动作必须人工签核，事故判定标准和自动化剧本的边界由安全团队定义，MCP 与 API 把编排延伸进现有 ITSM。ISOC 的告警分诊与攻击调查 Agent 已 GA，应用渗透测试与跨云修复仍是预览。

Agent 身份治理第一次以产品形态出现。 Agent 365 与 Entra 的 Discovery 会给发现的 Agent 分配身份，纳入身份治理；Intune 可以约束终端上的本地 Agent；Defender 与 Purview DLP 管运行时访问与敏感数据。覆盖范围包括 AWS、GCP 上的第三方云 Agent，以及 60 种本地 Agent 类型，含 Claude Code、Codex、GitHub Copilot。

这四件套——身份、权限、运行时、审计——才是「企业敢不敢让 Agent 动手」的真正门槛。模型能力早就够了。

行业动态

EY 上线 Agentic Cyber Defence Centre（11 月 19 日）。 把微软的安全平台与 EY 的网络安全 IP、EY.ai Value Blueprints 结合，核心卖点不是「更快」，而是政策化控制 + 防篡改记录：Agent 能做什么、谁授权、事后怎么复核。EY 把自己当作 Client Zero 先跑一遍，再对外输出可复用模式。

防篡改记录并不保证 Agent 判断正确，它的价值是让判断可被追究。这句话应该写进每一份 Agent 采购需求里。

Railway 被偷的 AI Key 烧掉约 74 万美元（11 月 17 日）。 攻击者专挑 AI 供应商凭证，最多解密了 1.85% 的工作区（约 10 万个）的环境变量，另有 1,852 名用户的关联令牌被重置。用途包括模型蒸馏与 LLMjacking——把偷来的额度通过「中转站」转卖。

真正的新问题是账单归谁：AWS Bedrock 与 Google Gemini 已按欺诈政策退款，OpenAI 与 SpaceXSI 逐案审核，Anthropic 与 OpenRouter 按「不退款」条款执行、由 Railway 自己兜底。同一场事故，五家供应商五种答案。API Key 的法律属性，比它的技术属性落后了至少两年。

关联事件还在扩散。 Fireworks AI 披露两起相关事故，其中一起经第三方云厂商波及 Notion——不到 1% 的工作区可能受影响，Notion 已下线 Insights 并停止通过 Fireworks 提供开源模型。受影响客户的系统本身没被攻破，问题全出在中间商这一层。

Commonwealth Bank 用 AI 更早发现软件漏洞，NATO 用 AI 做网络安全与威胁检测。银行与军事组织同时把 AI 放进防御链路，说明这件事已经过了实验期。

技术洞见

一、安全 Agent 的双向工业化，收敛到「授权与审计」

把今天的东西排在一起，攻防两侧其实走的是同一条流水线：把经验判例化，把判例技能化，把技能自动化。

两侧的差别不在智能，而在约束。攻击侧唯一的约束是法律与授权范围，防御侧则要在每一步插入审批。这也解释了为什么「防篡改记录」会从合规术语变成产品卖点：当 Agent 开始动手，组织需要的不是「它很聪明」的证明，而是**「它做了什么、谁批的、能不能查」的证据链**。

一个不太舒服的推论：防守方的响应窗口正在被压缩到小时级，而审批流程天然是分钟到天级。这个速度差不可能靠「更快的 SOC」解决，只能靠事先把授权粒度切细——把「能不能隔离这台机器」这种问题，在事发前就变成策略，而不是在事发时找人签字。

二、技能正在形成分发层，标准即入口

从仓库到运行时，中间正在长出一整层基础设施：

昨天说「技能是基础设施」，今天可以更具体一点：基础设施的争夺点从来不是内容，而是标准与分发。Google 出 stitch-skills、Cursor 出 plugins 规范，做的都是同一件事——让别人的技能跑在自己的运行时上。

对写技能的人来说，接下来的判断标准会变得很像软件包：

  1. 可验证：技能宣称的效果，能不能被一个测试用例证明？
  2. 可撤销：出错时能不能一键回滚到上一个版本？
  3. 可计费：谁为 token 和工具调用付钱，怎么结算？
  4. 可审计：它读了哪些数据、调了哪些工具，有没有记录？

四条里缺两条以上的技能，在个人机器上玩玩没问题，进不了企业。而一旦进了企业，「技能作者」这个身份就会第一次拥有软件供应链的责任——这既是机会，也是接下来一年最容易被低估的风险面。
