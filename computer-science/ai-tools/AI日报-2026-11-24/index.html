今日热点

今天的主题词是账面与实测。Nvidia 在六天内把黄仁勋请回 CEO 位，股价一周跌 14%，SEC 开始查它的会计实务；Anthropic 创纪录 IPO 之后，Dario Amodei「用沉浸式游戏安抚 AI 失业人群」的旧言论被 WSJ 翻了出来；Uber 花超了 AI 预算，转头把编码工具的上下文和推理档位往下调；VentureBeat 实测 Claude Fable 5.2，花三倍价钱买到几乎相同的结果。模型侧同样在被拆账：Z.ai 的 GLM-5.4 靠「28 层跑两遍」去够四倍体量的对手，GPT-6.2 Astra/Sol 在重度用户口中「基本不可用」。榜单第一名仍是 Claude-BugHunter，只是单日增速从 +2,037 降到 +1,833。

GitHub 热门 AI 项目

1. Claude-BugHunter —— 第六天榜首，增速第一次掉头（+1,833 Star）

elementalsouls/Claude-BugHunter 今天 2.08 万 Star、2,185 Fork、单日 +1,833，Python 实现。内容仍是那套：84 个技能、15 个斜杠命令、681 份已披露报告的模式库、24 类核心漏洞，外加企业身份与基础设施攻击矩阵。

连续六天霸榜之后，增速首次低于前一日（+2,037 → +1,833），这个信号比数字本身更值得读。前两天我写过「内容没变、Star 却加速」，说明涌入的人买的是工作流的可复制性；而增速回落意味着第一波「我要一份检查清单」的需求已经被吃完了，剩下的人在等第二件事：这套判例到底还准不准。

2. superpowers —— 32 万 Star 之后，方法论开始收「路由税」

obra/superpowers 今天继续留在榜单第二，Star 已过 32 万。它把「追问需求 → 分块确认规格 → 写实施计划 → 子代理逐任务执行 → 审查 → 完工验证」固化为一套自动触发的技能。

上周我判断它的成熟形态不会是「全量加载」，而是带预算感知的分级触发。今天榜单上同时出现 last30days-skill、stitch-skills、diagram-design 这类单一职责技能，正好从侧面印证了这一点：当通用流程框架变得足够重，用户会绕开它，直接装一个只干一件事的技能。生态的演化方向不是「一个大框架吃掉所有场景」，而是框架退化为调度器，技能变成可插拔的零件。

这对写技能的人是个提醒：与其做一个「什么都能干」的技能，不如做一个边界清楚、失败时能明确说「这不是我的活」的技能。

3. CLI-Anything —— 6.43 万 Star，把「软件接入」变成内容工程

HKUDS/CLI-Anything 今天 6.43 万 Star、5,864 Fork、+1,075，配套 CLI-Hub 已成为社区分发 harness 的入口。路线依旧锋利：不教 Agent 看屏幕，而是给每个软件造一层 CLI。

它最有价值的设计不是「能操作软件」，而是把操作变成可审计的事件流。视觉点击方案在这一层几乎无能为力：截图里没有语义，坐标随窗口漂移，失败时也说不清是哪一步错了。而 CLI 的每一次调用都有参数、有返回码、有耗时，天然适合做日志和回归。

风险同样在这一层。社区产出的 harness 质量参差，而 Agent 拿到的权限是真实的——一个写错的删除命令，代价不会因为它是「社区贡献」而降低。所以 CLI-Hub 迟早要做的事不是扩品类，而是给 harness 分级授权：只读、可写沙箱、可写生产，三档分明。

4. minimind —— 接近 7 万 Star，两小时训一个 64M 模型的教育价值

jingyaogong/minimind 今天仍在榜，主张「两小时从 0 训出你的 64M 大模型」，分词、预训练、SFT、LoRA、DPO、推理部署一条流水线跑完只要一个下午。

它的价值从来不在指标，而在降低判断力的门槛。亲手跑过一遍的人，听到「我们的模型在某某榜单上超过 GPT」时会本能地追问：训练数据从哪来、评测集有没有污染、tokenizer 是不是同一套、few-shot 示例怎么选的。这些追问不需要博士学位，只需要一次完整的失败经验。

在一个能力不断被营销化的市场里，这种经验比任何 benchmark 图表都更能防忽悠。这也是它连续多日留在榜上的真正原因——它不是工具，是教材。

5. firecrawl —— 20 万 Star 级，抓取层就是 Agent 的输入层

firecrawl/firecrawl 稳居榜单，自我定位早已从「网页爬虫」改为「Knowledge infrastructure to make your agents smarter」：搜索、抓取、解析，550+ 数据源收敛成一个 API。

这条转型线说明 Agent 工程的瓶颈已经换位——推理不再是主要失败点，脏上下文才是。导航栏、广告位、cookie 弹窗、动态渲染的空壳 DOM，都会被当成事实塞进窗口，模型再强也只能在垃圾上做推理。抓取层真正的工作量在清洗、去重、结构化和增量更新，而不是发 HTTP 请求。

代价是它正在从工具变成中间商。谁被聚合、谁被优先返回、原创内容方能否分成——这套问题搜索引擎时代已经演过一遍，Agent 的输入层迟早要面对同样的监管与商业博弈。

6. openvino —— 新上榜：端侧推理的「工程底座」被重新看见

openvinotoolkit/openvino 今天进入榜单。它不是新项目，而是 Intel 的推理优化与部署工具链：模型转换、量化、算子融合、跨 CPU/iGPU/NPU 的统一运行时。

它此刻上榜不是偶然。过去一周的叙事主线之一是「小模型跑在本地」——Thinking Machines 的 Inkling 2 mini、minimind 的 64M 教学模型，都在把注意力从云端拉回设备。而把一个训练好的模型真正跑进笔记本，中间隔着的正是这类工具链：INT4/INT8 量化掉多少精度、哪些算子会回落到 CPU、NPU 的驱动版本怎么对齐。模型发布是新闻，部署工具链才是交付。

顺带一个观察：端侧推理的竞争焦点正在从「能不能跑」转向「跑起来后功耗和首 token 延迟是多少」。这两个指标不进 benchmark，但决定用户会不会真的用。

7. last30days-skill —— 新上榜：跨平台研究，然后合成一份有出处的摘要

mvanhorn/last30days-skill 今天新进榜。一句话：让 Agent 就任意主题，在 Reddit、X、YouTube、Hacker News、Polymarket 和开放网络上做研究，再合成一份有依据的摘要。

它踩中的需求很具体：单个平台的搜索都带立场偏差。Reddit 偏技术吐槽，X 偏情绪与转发，YouTube 偏长尾教程，Polymarket 的赔率则是对「会不会发生」的真金白银下注。把这几个信号放在一起交叉，才可能得到接近事实的判断。

但这类工具的核心难点不在抓取，而在来源加权与证据链。同一件事，一个 200 万粉的账号和一条 3 个赞的评论，权重不该相同；一条 2024 年的旧帖被当成今天的证据，结论就会偏。合成摘要如果不带出处、不带时间戳，读起来会比没有摘要更危险——因为它看起来很像结论。选这类技能时，优先看它怎么标注来源，而不是看它总结得多顺。

8. app-store-compliance —— 5,482 Star、+936：合规继续被写成可执行检查项

mjmirza/app-store-compliance 今天 5,482 Star、352 Fork、+936，Shell 实现。内容枯燥但值钱：124 条应用商店拒审模式与修复方案、隐私清单与 Data safety 检查、112 个跟踪中的合规截止日期（EU AI Act、DSA、COPPA、各州年龄法）。

枯燥正是护城河。合规知识的形态是「截止日期 + 判定条件 + 证据材料」，天生适合做成检查项而不是文档。一个应用被拒审一周，损失的是整个发布窗口；而这些信息散落在几十个官方页面里，没人愿意持续跟。

它对技能生态的提示很直接：下一个高价值品类可能是「法规」。法规有版本、有生效日、有地域差异、有判定标准——这四条正好是软件包该有的属性。

9. 平台侧：cursor/plugins 与 stitch-skills 的规范之争

cursor/plugins 今天 1.90 万 Star、2,057 Fork、+359，Fork 比例接近 11%，明显高于一般工具库，说明大量用户 Fork 后改自己的插件。google-labs-code/stitch-skills 则是 1.25 万 Star、+401，为 Stitch MCP server 提供遵循 Agent Skills 开放标准的技能库，兼容 Antigravity、Gemini CLI、Claude Code、Cursor。

一边是厂商发规范，一边是用户大量 Fork 改造，两件事同时发生只说明一件事：插件生态还没定型。规范太严没人用，太松没法审计。这个平衡点最终会由权限模型决定，而不是文档质量。

新工具/产品速览

GPT-6.2 Sol 聊天专用版（OpenAI）：针对对话场景调优，官方说法是「处理复杂请求更强，尤其是给详细指令或要求联网查资料时」。面向 Plus、Pro、Business、Enterprise 推送。同一周内 GPT-6.2 Astra 与 Sol 在重度用户那里收获了大量负评，VentureBeat 的标题直接写「essentially unusable」——同代模型在不同使用强度下的口碑分裂，是这周最值得记住的现象。

GLM-5.4（Z.ai）：思路是「跑两遍 28 层」来对标四倍体量的模型。见下方技术洞见。

Claude Fable 5.2（Anthropic）：VentureBeat 的 bug 修复实测显示，它花了比 Opus 5.5 多三倍的成本，拿到几乎相同的结果。这不等于模型差，但足以说明一件事：新模型的价格涨幅正在快于能力涨幅，选型时按任务价值分级比按榜单排名选更划算。

Meta Muse Agent：在英国上线。消费级 Agent 的地域扩张继续推进，监管差异仍是主要节奏控制器。

Fountain Orchestra：把 AI Agent 用于前线员工的招聘、排班与管理。蓝领用工是 Agent 落地最被低估的场景——流程标准化程度高、语言要求低、人工成本占比大。

Nothing 无屏 AI 设备：定档 12 月 8 日发布，官方口径是「AI 走出聊天框」。硬件形态能否成立，取决于它是否解决了手机做不到的事，而不是能否语音唤醒。

行业动态

Nvidia 六日之内先罢免、再请回黄仁勋。 叠加股价一周下跌 14%、SEC 调查其「会计实务」，以及黄仁勋基金会向 CoreWeave 投入 3.5 亿美元（超过 1 亿已花出），这条线的关键词不是产品，而是治理。当一家公司的市值叙事高度绑定单一人物与单一客户结构时，任何人事或会计层面的波动都会被放大成系统性风险。对下游团队的实际影响是采购条款：长约还是短约、能否转租算力、断供时的退出成本。

Anthropic 完成创纪录 IPO，创始人言论被重新审视。 WSJ 的深度报道提到 Dario Amodei 曾在内部讨论「用沉浸式游戏缓解 AI 导致失业带来的社会冲突」。这句话之所以刺耳，不在于它是否可行，而在于它默认了「失业不可避免」这个前提。IPO 之后，安全叙事与资本叙事的张力只会更紧——公开市场的季度节奏，和「慢一点、稳一点」的研发节奏天然冲突。

Loudoun County 暂停新数据中心申请一年。 这个被称为「数据中心巷」的弗吉尼亚县，成了全美第一个踩刹车的样本，估计影响 33 个在审申请。电力、水、噪音、地价——四个约束同时到顶。算力扩张的瓶颈正从「买不买得到芯片」转向「社区让不让建」。

Uber 砍掉 AI 编码工具的上下文与推理档位。 花超预算之后的直接反应，不是停用，而是降配。这个选择很现实，也很有代表性：企业不会因为 AI 好用就无限付费，单位产出的成本才是续约依据。

T-Mobile：给 AI 更多资料，回答反而更差。 这个案例值得单独记住。上下文窗口变大不等于效果变好，检索进一堆弱相关内容，模型会在噪声里做取舍，最后给出更自信但更错的答案。「更多上下文」是个需要被验证的假设，不是默认优化方向。

Etsy 修改 AI 条款。 在卖家集体反对后，Etsy 表示会修订新服务条款，明确不用卖家内容训练「复制其原创作品」的模型。平台与创作者之间关于训练数据的谈判，正在从舆论战进入条款战。

SpaceX 用芯片作抵押贷款，并把芯片送上太空。 抵押物在轨道上、债务放在表外特殊目的实体里—— lenders 不喜欢这个结构完全可以理解。它是当下算力金融化的一个极端切片。

技术洞见

洞见一：循环层——用计算换参数，是这一代小模型的共同选择

GLM-5.4 的做法被概括为一句话：跑两遍 28 层，去逼近四倍体量的对手。Thinking Machines 的 Inkling 2 mini 用的是同一族思路：前段与后段各跑一次，中间层用共享权重循环多次，等效深度远大于实际层数。

为什么这条路在 2026 年突然集体出现？因为权重占用是显存问题，计算量是时间问题，两者的价格曲线在分叉。参数翻四倍，显存和带宽都要翻四倍；而同样的权重多跑一遍，只增加 FLOPs。在端侧和推理成本敏感的市场上，后者的边际成本低得多。

但账要算全：

  • 收益：显存占用可控、能塞进消费级设备、量化后精度损失更小。
  • 代价：首 token 延迟随循环次数线性上升；KV cache 与批处理策略要重新设计；训练时的梯度路径变长，稳定性更难调。
  • 隐含风险：等效深度不等于等效能力。同一组权重反复处理同一份表示，容易在表征上「自我强化」——简单任务变快，需要多步推理的任务反而可能卡在同一个错误上。

所以「28 层跑两遍」不是免费的午餐，而是把空间换时间的经典交易搬到了模型结构里。它最适合的场景是：显存受限、延迟可容忍、任务以单步生成为主。反过来，长链推理和强交互场景，稠密大模型仍然占优。

洞见二：上下文与预算，正在成为 Agent 工程的一等公民

这周有三条新闻指向同一件事：Uber 超支后下调上下文与推理档位、T-Mobile 发现资料给多了反而更差、Fable 5.2 用三倍成本换来几乎相同的结果。三条合起来是一句话——「多给模型一点」不再是默认正确的优化。

这套闭环里有三个设计要点，缺一个就会退化成「月底看账单然后惊讶」：

  1. 归因粒度要到任务，而不是到 API key。同一把 key 上跑着代码补全、文档问答和批量摘要，混在一起就无法判断该砍谁。
  2. 降级要有预案顺序。先砍历史轮次还是先关推理？先换小模型还是先减少检索条数？顺序不同，用户体验的损失差一个量级。
  3. 成功率必须进指标。只盯成本，最省的做法是永远返回空字符串。成本与成功率必须成对看，否则优化方向必然跑偏。

把这两条洞见放在一起看，2026 年底的工程共识正在成形：能力增长不再主要来自「更大」，而来自「更会分配」——分配层数、分配上下文、分配预算。谁能在同样的账单下把任务分到合适的档位，谁的成本结构就更好看。而这，恰好也是今天 Nvidia 的股价、Uber 的预算表和 Claude 的定价表在同时讲的故事。
