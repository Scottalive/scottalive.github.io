今日热点

今天的主题词是分发的单位变了。GitHub Trending 前十六名里，有八个是「技能 / 插件」形态而不是应用形态——Claude-BugHunter 继续霸榜（第六天以后增速回落到 +1,600），superpowers、stitch-skills、diagram-design、last30days-skill 各自只干一件事。同一天，Anthropic 把 Skills over MCP 推进 public beta：MCP server 从此不只要送工具，还可以送操作手册，用户那边不用装任何东西。模型侧的对照则更有意思——Z.ai 的 GLM-5.4 用「28 层跑两遍」去够 2T–3T 体量的对手，同一周 Thinking Machines 的 Inkling 2 Mini 用同族思路把循环层塞进了笔记本。一端是把软件拆成技能分发，一端是把参数换成计算量，两件事都在回答同一个问题：怎么用更少的东西办成同样的事。

GitHub 热门 AI 项目

1. Claude-BugHunter —— 第八天榜首，增速落到 +1,600

elementalsouls/Claude-BugHunter 今天 2.39 万 Star、2,433 Fork、单日 +1,600，Python。内容：85 个技能、16 个斜杠命令、681 份已披露报告的模式库、24 类核心漏洞，外加企业身份与基础设施攻击矩阵。

对比两天前的数据（2.08 万 Star、+1,833），增速又降了一档，但绝对量仍然可观。更值得注意的是内容增量几乎停了：两天里技能从 84 变 85、斜杠命令从 15 变 16，而 Star 涨了三千。这个组合说明项目已经进入第二阶段——作者的重心从「扩表」转向「维护」，流量则在从「猎奇围观」转向「拿来当基线」。

这个转向会带来一个它自己也没准备好的需求：版本化。安全判例和模型权重不一样，它折旧得毫无仪式感。云厂商改一个默认配置、WAF 升一版规则、框架发一个 patch 版本，一批技能就从「有效」变成「误报制造机」，而没有任何东西会通知你。

真正决定这类项目能不能长期用的，是虚线那条边：有没有一个 CI 能跑「这条漏洞今天还能不能打」。没有它，技能库越大，误报率越高，最后用户会选择少装几个。这也是我对「技能生态」最基础的判断标准——不看数量，看它怎么处理失效。

2. CLI-Anything —— 把「软件接入」做成内容工程

HKUDS/CLI-Anything 的口号是「Making ALL Software Agent-Native」，配了一个 CLI-Hub（clianything.cc）。思路直白：Agent 操作软件的能力受限于软件有没有 CLI，那就把没有的补齐。

这条路的价值在于绕开了 GUI 自动化最脆弱的一环——像素坐标。能用 --json 拿结构化输出，就不该去截图点按钮。但它把风险从「看不见」换成了「看得见」：CLI 意味着真实副作用，rm、push、deploy 都是一行命令的事，错了没有确认弹窗。所以这类 Hub 真正的技术难点不是覆盖率，而是命令的危险等级标注——哪些命令只读、哪些需要 dry-run、哪些必须人工确认。缺了这一层，它就是把一把上了膛的枪递给一个刚学会走路的 Agent。

3. minimind —— 两小时，从零训一个 64M 模型

jingyaogong/minimind 的描述就一句话：两小时从 0 训出你的 64M 大模型。

把它和 GLM-5.4 放在同一天的榜单上看，反差非常有意思：一端是 750B 参数、循环层、云端集群；另一端是 64M、单卡、两小时。中间的每一层都被抽掉了，只剩下最核心的骨架——tokenizer、注意力、位置编码、反向传播。理解成本正在从「读论文」降到「跑一遍」，这是今年教育型项目最大的价值变化。

对已经写业务代码的人来说，跑完这一遍的收益不是学会训练模型，而是学会判断别人关于模型的说法是否可信。知道 64M 模型在什么任务上必然失败，就不会被「小模型也能打」的宣传带走；知道 loss 曲线的形状，就不会把训练不稳误判成数据问题。

4. firecrawl —— Agent 的供给侧基础设施

firecrawl/firecrawl 的定位已经从「爬虫」变成了「知识基础设施」：搜索、抓取、访问 550+ 数据源，一个 API。

这个转向值得记一笔。Agent 的瓶颈早就不是推理，而是拿到干净、结构化、可追溯的输入。网页抓取的三座山——反爬、动态渲染、正文提取——没有一座是模型能解决的，全是工程脏活。有人把它做成 API，等于把 Agent 的输入质量下限抬高了。

选型的判断点是可追溯性：返回结果里带不带原始 URL、抓取时间、以及正文提取的置信度。不带这些，下游的引用就是编的。

5. diagram-design —— 「技能即品味」，而且它明确反对 Mermaid

cathrynlavery/diagram-design 支持 Claude Code、Codex、Copilot、Cursor 等，52 种图表类型，输出自包含的 HTML + SVG。README 里那句 “No shadows. No Mermaid slop.” 基本就是它的产品宣言。

这是我今天看到最诚实的一个技能：它不假装自己在做「通用可视化」，而是把自己的审美主张写在门口。技能生态要成熟，必须允许这种「有偏好的工具」存在——因为默认值的质量决定了大多数人产出的质量，而 Mermaid 的默认值确实平庸。

（本文仍然用 Mermaid，因为 Hexo 渲染便宜。这是个成本取舍，不是审美判断。）

6. app-store-compliance —— 从 +936 掉到 +561，但方向没变

mjmirza/app-store-compliance 今天 6,813 Star、451 Fork、+561，Shell。125 条拒审模式、隐私清单与 Data safety 检查、117 个跟踪中的合规截止日期（EU AI Act、DSA、COPPA、各州年龄法）。

增速掉下来了，这很正常——它的用户是「正在被拒审的人」，不是「围观的人」，池子本来就小。但它验证的判断我认为仍然成立：法规是技能生态里最被低估的品类。法规天生具备四个软件包属性——有版本、有生效日、有判定条件、有地域差异。这种东西做成文档是浪费，做成检查项才是它该有的形态。

7. stitch-skills 与 cursor/plugins —— 规范之争进入第二年

google-labs-code/stitch-skills 1.32 万 Star、1,550 Fork、+308，为 Stitch MCP server 提供遵循 Agent Skills 开放标准的技能库。cursor/plugins 1.97 万 Star、2,126 Fork、+268，Fork 比例接近 11%，远高于一般工具库。

两个数字放在一起读：一边是厂商在发规范（而且互相兼容同一套标准），一边是用户在大量 Fork 改造。规范已经收敛，工具链还没收敛。 这是好事——标准统一之后，竞争会从「谁的格式赢」转到「谁的权限模型更让人敢用」。而后者，恰好是今天 Anthropic 那篇公告里最含糊的部分。

8. opensre —— 站内刚写过安装指南，它今天上榜了

Tracer-Cloud/opensre 定位是「开源 CI/CD 可靠性 Agent」。有意思的是本站两天前刚发过它的安装与实战指南，今天就出现在 Trending 上。

CI/CD 是 Agent 落地最被低估的场景之一：日志结构化程度高、失败可复现、判断标准明确（流水线绿了就是绿了）。它不需要模型有创造力，只需要模型有耐心——把 200 行日志读完，找到第一个真正的 error，而不是第 40 个 WARN。

新工具/产品速览

Skills over MCP（Anthropic，public beta）：Claude 与 Claude Code 里可以默认开启（Pro/Max/Ultra），Team 需管理员打开，Enterprise 待跟进。一个技能就是一个目录加 SKILL.md，通过 MCP 的 Resources 分发：连接时只发现清单，指令按需加载。同期 MCP 的 Tasks 扩展（长任务后台跑）与 Elicitation（服务端反问用户）转 GA，File Uploads 在路上——后者让客户端把文件直接传给服务端，不经过模型的上下文窗口。VS Code 1.147+ 也已支持。官方举例：Shopify 建店、HubSpot 客户上手、Atlassian 工作分析、Carta 起草股权。

GLM-5.4（Z.ai）：首个基于 Loop Transformer 的旗舰，750B 规模上把 28 层跑两遍。加了视觉，主打「Generalized Coding」——把代码能力延伸到机械设计与 3D 建模。已在 GLM Coding Plan / ZCode / Z.ai Chat 上线，API 待发，开源权重「安全加固后跟进」，未给日期。见下方技术洞见。

Inkling 2 Mini（Thinking Machines Lab）：同族循环层思路，主打在笔记本上本地跑。上周发布，本周被 GLM-5.4 的公告顺带带火。

Performance Factory（OpenAI）：Codex 驱动的软件优化系统，用来让 ChatGPT 自己保持快。内部工具外露，说明「用 AI 优化 AI 基础设施」已经从实验变成产线。

Snowflake 的预算观：在 token 排行榜和支出上限之后，它的第三个想法是保留上限，然后研究谁把它撞破了。这是个很聪明的设计——上限是成本控制，撞线记录是需求信号，两者本来就不该分开看。

行业动态

近半数受访工程师与管理者表示：写代码的 Agent 也在审这些代码。 这个数字比它看起来更麻烦。自我审查的问题不是「模型会不会放水」，而是写和审共享同一套盲区。同一个模型在同一份上下文里犯的错，换个角色不会自动消失。真正有效的做法是引入不对称：换模型、换上下文、换提示词，最好再加一条静态检查兜底。

Nvidia 六天内把黄仁勋请回 CEO 位。 一周前刚表态「不回归」，六天后改口。叠加此前的股价波动与会计实务调查，这条线的关键词仍是治理而非产品。对下游的实际影响在采购条款：长约还是短约、算力能否转租、断供时的退出成本。

Uber 超支后下调编码工具的上下文与推理档位；T-Mobile 给 AI 更多资料，回答反而更差。 两条合起来说的是一件事：「多给模型一点」不再是默认正确的优化。上下文窗口变大不等于效果变好，检索进一堆弱相关内容，模型会在噪声里做取舍，最后给出更自信但更错的答案。

Claude Fable 5.2 在 bug 修复实测里花掉 Opus 5.5 三倍成本，结果几乎相同。 这不等于模型差，但足以说明新模型的价格涨幅正在快于能力涨幅。按任务价值分级，比按榜单排名选型更划算。

「你的模型通过了所有测试」——然后呢。 VentureBeat 那篇讲的是最常见的失效模式：模型在干净、熟悉的材料上被测试，然后毕业进入生产环境，输入变脏、标签漂移、没人给你按曲线打分了。实验室里的优秀，和生产里的静默退化，是两件事。

最快的 AI 集群也可能被发布流水线拖住。 一篇关于固件灰度发布的复盘：自动化在第 1:14 自己停了，因为某个 zone 的非正常重启比例越过安全阈值。这类文章的价值在于它写出了「自动化的正确行为是停下来找人」，而不是「自动修好」。

技术洞见

洞见一：技能成了可分发的软件包，但权限不能由包自证

把今天的两条线拼起来看：Trending 上一半是技能包，Anthropic 让 MCP server 也能送技能。这意味着**「技能」正式成为一种分发单位**——和 npm 包、Docker 镜像、VS Code 插件同级别的东西。

这条链路里最关键的裁决点在 D，而这正是公告里最含糊的地方。原文说得很清楚：Claude Code 会忽略 MCP 技能自己声明的一部分设置，包括工具权限和 hooks。换句话说，一个技能包不能自己宣布「我有权删文件」。这个决定是对的——如果包能自证权限，那它就是 npm install 的 postinstall 脚本问题再来一遍。

但「客户端裁决」立刻带来第二个问题：裁决依据是什么。默认的 auto 模式靠一个分类器判断「这个技能能不能不经询问就加载」，这在低风险场景下很顺，在高风险场景下就是黑箱。企业真正需要的不是更好的分类器，而是三样朴素的东西：

  1. 来源分级：官方连接器、内部私有 server、第三方公开 server，三档不同的默认策略。
  2. 按技能粒度管控，而不是按 server。一个 server 同时提供「查文档」和「改生产库」两个技能，一刀切禁用等于放弃它。
  3. 加载即审计。技能在什么时候被加载、被哪个任务触发、之后产生了哪些工具调用，要能串成一条可回放的链。

再看官方举的例子——Shopify 建店、HubSpot 客户上手、Carta 起草股权——共同点是它们都在动真实资产。这类技能一旦被自动加载并在错误的上下文里执行，损失不是一次重试能挽回的。所以我对这个 beta 的判断是：体验会很顺，治理会在半年内成为主要吐槽点。而半年后赢的，不是技能最多的那个 server，是第一个把「谁能改什么」说清楚的那个。

顺带一个观察：File Uploads 那条不起眼，但影响的架构面比 Skills 大。文件不进上下文窗口，意味着大文件的处理从「塞进去」变成「传过去」，token 账本会重算一遍。

洞见二：循环层是把空间换时间搬进模型结构

GLM-5.4 的做法一句话：28 层跑两遍，不改参数量，只加计算量。

真正值得学的是它没说出口的部分：朴素地把层跑两遍是训不起来的。三个补丁各自对应一个具体故障：

  • 门控渐进更新：同一组表示被反复更新会发散。per-token 门控让第一遍「小步写、建全局」，第二遍「大步写、补细节」，并且按 token 难度调步长——越难的 token 第一遍写得越狠。这本质上是个由难度驱动的时间分配器。
  • 混合 KV cache：第二遍不复用整套 cache，而是复用第一遍的稀疏部分，第二遍只多存一个滑动窗口。显存增长被压住了。
  • 稀疏注意力索引复用：第二遍直接用第一遍的 indexer 结果，实验说与重算几乎等价。

为什么这条路在 2026 年集体出现？因为权重占显存，计算量占时间，而这两条价格曲线在分叉。参数翻四倍，显存和带宽都要翻四倍；同样的权重多跑一遍，只增加 FLOPs。在端侧和推理成本敏感的市场上，后者的边际成本低得多。

但账要算全：

维度 循环层 等参数稠密堆叠
显存占用 低（权重复用） 高
每 token 计算量 高（×2） 低
首 token 延迟 随循环次数线性上升 稳定
训练稳定性 需要门控等结构补偿 相对成熟
长链推理 有「陷在同一错误」的风险 更稳

Z.ai 自己承认 GLM-5.4 会陷入过长的推理循环——这几乎是循环结构的宿命：同一组权重反复处理同一份表示，容易在表征上自我强化。简单任务变快，需要多步跳跃的任务反而可能卡住。它给出的对比也值得打个折：主要受控证据来自一个 30B 测试模型（同样配置下多用约 10% 训练算力，MMLU-Pro 约 +15%，GPQA-Diamond 约 +12%，输出长度还短了一些），而「接近 2T–3T 体量」这句没有方法论。

所以「28 层跑两遍」不是白捡的便宜，是把空间换时间的经典交易搬到了模型结构里。它最适合的场景很清晰：显存受限、延迟可容忍、任务以单步生成为主。反过来，长链推理和强交互场景，稠密大模型仍然占优。

把两条洞见放一起看，今天讲的其实是同一门手艺：怎么用更少的东西办成同样的事。技能那条线是把一个大系统拆成可分发的小零件，代价是治理复杂度转移给了客户端；循环层那条线是把参数换成计算，代价是延迟和稳定性。两条线都没有免费的午餐，只是交易的位置不同。而工程判断力，说到底就是知道自己在跟谁做交易。
